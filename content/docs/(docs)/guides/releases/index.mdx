title: Releases
description: How your source becomes an image, what triggers a new one, and how to undo it.
---

Every deploy runs through the same three concerns, in order. Only sources Deplo builds have any of
them: a Docker image app skips build settings entirely, and neither a Docker image nor a Compose
stack can roll back, because there is no single image Deplo owns for either.

**Build settings** decide how your source becomes an image: which builder runs, what commands it
runs, and which port the result listens on. Most apps never touch this, because detection handles
it. [Learn more ->](/guides/releases/build-settings)

**Automatic deployments** decide what makes a *new* build happen: a push to a tracked branch, a
new tag, or a call to a deploy hook URL you hold.
[Learn more ->](/guides/releases/automatic-deployments)

**Rollbacks** decide what happens when a build was wrong: go back to an image that already worked,
in seconds, with no rebuild. A rollback does not undo a deploy trigger, so turn off deploy on push
first if you are rolling back because the branch itself is broken.
[Learn more ->](/guides/releases/rollbacks)
