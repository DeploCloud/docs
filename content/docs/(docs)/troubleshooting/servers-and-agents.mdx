## A server is stuck provisioning

`provisioning` means the agent has never called home. On the machine, run:

```bash
systemctl status deplo-agent
journalctl -u deplo-agent -f
```

| What you see | Cause |
| --- | --- |
| The unit does not exist | The install command never ran, or failed early |
| `Refusing to run an unverified binary` | The download did not match its checksum. Retry; if it persists, something is intercepting it |
| The unit runs but nothing happens | It cannot reach the panel. Check that the machine is connected to the internet, and the address in the command |
| `bootstrap token` errors | The token was used already, or it expired. Issue a new one from the server's menu |
| `status=216/GROUP` | The unit wants the docker group and Docker is not installed. That is expected on a backups-only host, and its unit is installed without it |

## A server is offline

`offline` means the server has not been connected to Deplo for about 10
seconds. Its card says `Check that the machine is on and connected to the internet.`

There is no port to open. The server connects to Deplo by itself, and is
back online within seconds of reaching the internet again.

| What you see | What to do |
| --- | --- |
| The machine is off, or has no internet | Start it or reconnect it. Nothing else to do |
| The machine is on and online | Check the agent on it: `systemctl status deplo-agent`, then `journalctl -u deplo-agent -f` for why it cannot reach the panel |
| It was already offline before Deplo's last update | Its agent is too old to connect by itself, and Deplo cannot update an agent it cannot reach. [Reinstall the agent](#an-agent-needs-to-be-reinstalled) and it connects on its own |
| The panel's address changed while it was off | See [below](#a-server-was-off-while-the-panels-address-changed) |

## A server was off while the panel's address changed

A connected server learns a new panel address at once. One that was off at
the time still knows the panel's backup address, the generated one like
`deplo-cb00710a.deplo.site`, and connects there.

It cannot find the panel when neither address it knows works any more: the
domain changed while the backup address was off, or the panel has no domain
of its own and its generated address changed. Then [reinstall the agent](#an-agent-needs-to-be-reinstalled)
with a fresh install command. A panel domain, with the backup address left
on, avoids this.

## A server hasn't connected to Deplo yet

While an update waits on a server, **Settings -> Deplo -> Updates** names it:

`edge-2 hasn't connected to Deplo yet. Check that it's turned on and connected to the internet.`

A server connects to Deplo by itself once Deplo has updated its server agent, usually moments
after the update. Its apps keep running. Until it connects, a deploy, logs or the console on it
are refused with:

`This server can't connect to Deplo yet. Its server agent connects on its own once it is up to date: if it still can't in a few minutes, check that the server is connected to the internet.`

Find the server under **Settings -> Servers**:

| What you see | What to do |
| --- | --- |
| **Offline** | The machine is off or has no internet. Start it or reconnect it. Deplo updates its server agent once it is back, and it connects by itself |
| **Degraded**, with `This server can't reach Deplo at deplo.example.com. Check that it's connected to the internet.` | Deplo reaches the server, but the server can't reach Deplo back. Check that the machine is connected to the internet and that its network lets it reach `deplo.example.com`. The **Server cannot run apps** alert says the same |
| `Unusable - Update failed, retrying in 4 min` under its name on the Updates tab | Its server agent has not updated yet. Wait for the retry, or [retry it by hand](/operations/update#retry-an-update-by-hand) |
| A machine you no longer use | [Remove it](/operations/remove-a-server-or-uninstall), or [leave it behind](/operations/update#leave-a-server-behind) so the update stops waiting for it |

## A server was left behind

An instance admin left this server behind, so Deplo could update without it. The Updates tab
says:

`edge-2 was left behind: it needs its server agent reinstalled after the update.`

- **Before the update,** nothing changes for it. If it connects by itself, it drops off the
  list and works normally.
- **After the update,** it won't work until its server agent is reinstalled. Its apps keep
  running, and its apps and settings stay in Deplo.

To bring it back, reinstall its server agent:

1. Open the server under **Settings -> Servers**, then **Advanced -> Install command**.
2. Click **Reissue install command**, and run the command it shows on the server.

It connects by itself and comes back as it was, with its apps. See
[An agent needs to be reinstalled](#an-agent-needs-to-be-reinstalled) if the command fails. A
server you no longer need can be [removed](/operations/remove-a-server-or-uninstall) instead.

## A server says warning, error, offline, or Unknown

| Value | Means | Where to look |
| --- | --- | --- |
| `warning` | The agent is up and trusted, Docker is not answering | `systemctl status docker` on the host |
| `warning` that says it can't reach Deplo | The server answers Deplo, but can't reach Deplo back | [A server hasn't connected to Deplo yet](#a-server-hasnt-connected-to-deplo-yet) |
| `error` | Something answered, but its agent is wrong: untrusted certificate, unsupported contract, or an application error | Re-run the install command to re-enroll |
| `offline` | Not connected to Deplo for about 10 seconds | [A server is offline](#a-server-is-offline) |
| `Unknown` | The stored reading is stale | Click **Refresh** |

<Callout type="info">
Health is a stored reading. A deploy performs a live handshake, so a green
card and a failing deploy can still happen together.
</Callout>

## Check readiness instead of guessing

Use **Check readiness** in the server's menu for one live check of the agent,
Docker, routing, capacity, build methods, and Deplo configuration.

`fail` blocks a deploy. `warn` means it can deploy but is not fully usable.
`skip` means the check could not be evaluated, not that it passed.

## Metrics show dashes

The telemetry stream is not connected. Refresh the server health first.
History is held in memory and starts empty after a panel restart.

## A deploy says Docker cannot create a network

Deplo uses one Docker network per **Environment**. If the installer could not
restart Docker because containers were running, the configured address pool is
not active yet. Restart Docker in a maintenance window; the file is already
correct.

## A deploy fails with No chain DOCKER-FORWARD

Docker's forwarding chains were removed underneath it. Restart Docker to
recreate them.

## A removed container still appears

Deplo retries an unconfirmed teardown and raises an alert if it gives up.
Removing the server drops its pending teardowns.

## The install command returns 503 or cannot resolve a release

The panel cannot reach `github.com` to resolve or checksum the agent release.
Restore outbound access from the panel's machine, then run the command again.

## The install command contains 127.0.0.1

That address is for the machine running the panel. Paste it there only;
another server needs the panel's public address.

## An agent needs to be reinstalled

Run a fresh install command from the server's **Advanced** tab. It clears the
old certificates, so an expired or already-used token leaves the agent with
`unknown-token`. Issue a new token from the server's menu first.

## A server is permanently gone

Remove it in Deplo. This revokes trust and does not require the machine to
answer. See
[Remove or uninstall](/operations/remove-a-server-or-uninstall).
