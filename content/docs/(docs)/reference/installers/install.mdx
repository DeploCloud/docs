---
title: install.sh
description: Installs the whole platform, Docker, Traefik, Postgres, the control plane and the agent, on a fresh server.
---

```bash
curl -fsSL https://deplo.build/install.sh | bash
```

With no flag it asks nothing and serves the dashboard on a generated host like
`deplo-cb00710a.deplo.site`. `--domain` puts it on a hostname of your own. Environment
variables the script reads: [Platform variables](/reference/environment-variables#variables-read-by-installsh).

<Callout type="info" title="Requires">
  Root (a downloaded copy re-runs itself through `sudo`), Bash 4, `curl`, `openssl`, and Docker
  Compose v2 when Docker is already on the host. Docker and `git` are installed if missing.
  Without `systemd` the panel still comes up, but the machine cannot become a Deplo server.
</Callout>

## Preflight checks

**These stop the run**, unless you pass `--force`:

- Architecture other than `x86-64` or `arm64`, Bash older than 4, no `curl` or `openssl`.
- **Less than 8 GB free on `/`.**
- Ports `80`, `443` or `3000` held by something that is not Deplo, or none of `3101` to `3104` free.
- No outbound HTTPS to `ghcr.io`, or to `get.docker.com` when Docker has to be installed.
- Docker present but its daemon not answering, or without Compose v2.

**These only warn:**

- **Less than 4 GB of RAM, fewer than 2 cores, or less than 30 GB free.** Deplo and Postgres
  fit in about 1 GB; 4 cores and 8 GB is the comfortable size for your apps.
- No `systemd`.
- The domain does not resolve here yet, or Let's Encrypt is unreachable.

## What the installer does

- Installs Docker and `git` when needed, and sets Docker's address pools unless a pool exists.
- Creates `/opt/deplo` (`.env` generated once, mode `0600`), the `deplo` network and the proxy.
- Starts Postgres, the control plane on `127.0.0.1:3000`, and Traefik, which serves it over HTTPS.
- Keeps the first free of `3101` to `3104` on `127.0.0.1` for this machine's own server agent.
- Writes the host CLI `/usr/local/bin/deplo`: `recover`, `update`, `logs`, `restart`.
- Once the panel answers, installs the server agent with the same
  [`install-agent.sh`](/reference/installers/install-agent) every other server runs.

On a machine that already runs another panel, the install is a **takeover**: Deplo waits
on free ports while you migrate. See [Migrations](/migrations).

<Callout type="info" title="Re-running it is the update path">
  On a machine with `/opt/deplo/.env`, it updates in place:
  - Never rotates a secret; keeps the domain, the address kind and the agent link port.
  - Dumps the panel's database to `/opt/deplo/backups/pre-update-<time>.sql.gz` first (3 kept).
  - Rolls the image back if the new version does not answer within 2 minutes.
  - Below an [update stop](/operations/update), installs the stop instead.

  A failing agent step is only a warning: the panel stays up and a re-run retries it.
</Callout>

## IPv6

The installer picks the kind of address the dashboard is served on:

| Server has     | Default | Generated address                                       |
| -------------- | ------- | ------------------------------------------------------- |
| IPv4 and IPv6  | IPv4    | `deplo-cb00710a.deplo.site` (`203.0.113.10`)            |
| IPv4 and IPv6, with `--ipv6` | IPv6 | `deplo-v6-2001-db8--10.deplo.site` (`2001:db8::10`) |
| IPv6 only      | IPv6    | `deplo-v6-2001-db8--10.deplo.site` (`2001:db8::10`)     |

```bash
curl -fsSL https://deplo.build/install.sh | bash -s -- --ipv6
```

The choice is kept in `.env` as `DEPLO_IP_FAMILY`; pass the other flag on a re-run to switch.
A server that lost its kind moves to the one it still has. On IPv6 the installer also:

- Gives every Docker network an IPv6 range (Docker 27 or newer). Existing Deplo networks move
  across without restarting their apps.
- IPv6-only: routes `ghcr.io` and `github.com` through public NAT64 resolvers
  (`DEPLO_NAT64_DNS` picks your own), unless the network already translates.
- IPv6-only: installs `deplo-clat` (464XLAT through `tayga`), so apps that dial IPv4 first
  still reach IPv4-only sites.

Docker is restarted only when no app is running; otherwise restart it in a maintenance window
and re-run. Apps' own addresses are set per server, under
[Generated addresses](/operations/servers/maintenance-and-advanced#generated-addresses).
