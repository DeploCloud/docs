---
title: Your First Deployment
description: What happens between `deplo up` and a live URL.
---

Running `deplo up` triggers a pipeline with four stages.

<Accordions type="single">
  <Accordion title="1. Detect">
    Deplo reads your repository (`package.json`, lockfile, config files) and
    picks a build preset. Next.js, Astro, Vite, and static sites are detected
    automatically; anything else falls back to a Dockerfile if present.
  </Accordion>
  <Accordion title="2. Build">
    Dependencies are installed and the build command runs inside an isolated,
    cached container. Build cache is reused across deployments on the same
    branch, so most rebuilds finish in seconds.
  </Accordion>
  <Accordion title="3. Deploy">
    The build output is uploaded and a preview URL is assigned:
    `<branch>-<project>.deplo.app`. The deployment is immutable, it will never
    change after this point.
  </Accordion>
  <Accordion title="4. Promote (optional)">
    Promoting a deployment points your production domain at it. Nothing is
    rebuilt, promotion just repoints traffic, which is why rollbacks are
    instant.
  </Accordion>
</Accordions>

<Callout type="info">
  Every push to a connected branch repeats this pipeline automatically. You
  only need `deplo up` for manual or local deployments.
</Callout>
