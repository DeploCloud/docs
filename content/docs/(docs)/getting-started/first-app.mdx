Deploying is one wizard with three cards. Only the middle card changes with the source you pick.
The build runs on the server you choose, never on the control plane.

## Deploy it


<Steps>
<Step>

### Open the wizard

On the Overview, open **Add new**, then **Application**.

</Step>
<Step>

### Pick where the code comes from

Five sources: **GitHub**, **Git**, **Docker Image**, **Compose** and **Upload**. Click one to go
to the next card. **Template** opens the catalogue instead.

<Tabs items={['GitHub', 'Git', 'Docker Image', 'Compose', 'Upload']}>
<Tab value="GitHub">

If no GitHub App is connected yet, click **Connect GitHub** and follow GitHub's screens. Deplo
creates the App for you, nothing to copy and paste. Choose the repositories it may see, then pick
the repository and branch. See [GitHub](/guides/git-providers/github).

</Tab>
<Tab value="Git">

Pick the provider, paste the repository URL, and set the branch. See
[Git connections](/guides/git-providers/git-connections) for GitLab, Bitbucket and Gitea.

</Tab>
<Tab value="Docker Image">

Type the image reference, like `ghcr.io/acme/api:v2.3.1`. The field autocompletes from public
registries and from your private registries. The app is named after the image and the port comes
from the image itself. This card has the **Deploy** button. Nothing is built, the agent only pulls
the image. See [Deploy a Docker image](/guides/deploy/docker-image).

</Tab>
<Tab value="Compose">

Click **Write compose** and paste your `docker-compose.yml`. The editor checks it as you type and
tells you what will be rewritten, what needs a permission, and what is refused. This card has the
**Deploy** button. See [Compose apps](/advanced/compose-apps).

</Tab>
<Tab value="Upload">

Drop a compressed archive of your project, or click to browse. The agent unpacks it and builds it
like a Git clone, with framework detection. This card has the **Deploy** button. See
[Upload your code](/guides/deploy/upload-code).

</Tab>
</Tabs>

</Step>
<Step>

### Set up the app

**GitHub and Git only.** Deplo has already read the repository, so this card is filled in:

- **App name**, taken from the repository.
- The framework it found, and the container port that framework uses.
- **Build command** and **Deploy command**, read from your `package.json` and written for your
  package manager. **Reset** empties a field and lets the builder decide.
- **Automatic deployments**, on, so every push to that branch deploys.

</Step>
<Step>

### Deploy

Click **Deploy**, bottom right. The server, the URL and the build method are already set. For a
repository or an upload, the agent detects the framework and builds an image with **Railpack**
by default, so you need no Dockerfile.

You land on the live build log. Closing the tab or reloading the page does not cancel anything.

</Step>
</Steps>

## What is under Advanced

Every card with the **Deploy** button has an **Advanced** drawer. It shows the target server on
its label.

| Setting | What it is |
| --- | --- |
| Deploy to | Which server runs it. A single-machine install has one, already picked. |
| Environment variables | Type them, or tick the team's [shared variables](/guides/config/shared-variables). Both reach the first build. |
| Build method | Railpack, Nixpacks, a Dockerfile, or a static site, with its version and the container port. |
| Port | Docker images only: the port routing uses, read from the image and editable here. |
| Build path | The sub-folder to build from, for a monorepo. |
| Build on | Another server to build on. Automatic uses a [build server](/advanced/build-servers) if you have one. |
| Git | Deploy on push or on tag, watch paths, submodules. |
| Extra compose flags | Compose stacks only: what to append to `docker compose up`. |

## What you get

When the badge turns **Running**, the app header shows the production URL and a **Visit** button.

<Image
  src={`${basePath}/screenshots/first-app/04-app-overview.png`}

  width={1728}

That first URL is a free `deplo.site` hostname that points at your server with no DNS setup. It is
served over **plain HTTP**, because a `deplo.site` hostname cannot have a certificate. See
[Add a domain](/getting-started/add-a-domain) for a hostname with HTTPS.

## The tabs you now have

| Tab | What is there |
| --- | --- |
| Overview | The production deployment, the last four builds, the URL |
| Deployments | Every build, with **Redeploy**, **Rollback** and **Delete** |
| Domains | Add your own hostname |
| Environment | Variables for this app |
| Logs | What the container is printing, live |
| Monitoring | CPU, memory, network and disk for this app |
| Backups | Schedules and restores |
| Settings | Source, build, storage, resources, access, danger zone |

Console, Cron jobs and Pull requests appear once you turn them on or once they have something to
show.

## Good to know

- **The name is permanent.** The display name can change, the slug used in URLs and volume names
  cannot.
- **The first build is the slow one.** Later builds reuse the server's build cache. Docker Image
  apps never build.
- **A private repository needs a connection, not a key in the URL.** Connect the provider once in
  **Settings -> Git** and every app reuses it.
- **A private registry needs credentials in Settings -> Registries**, not in the image reference.
- **`Error` means the last deploy failed, not that the app is down.** See
  [App status](/concepts/apps-projects-and-environments#app-status-is-intent-not-observation).

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The build fails on a missing command | Your repository has no `build` or `start` script, so the builder guessed. Set both in **Settings -> Deployments**. Applies to GitHub, Git and Upload. |
| The app starts and the URL times out | The container listens on a different port than the one Deplo routes to. Fix the port in **Settings -> Deployments**, or per hostname in **Domains**. |
| The repository picker is empty | The GitHub App has no access to it. Click **Manage connected apps** and grant the repository on GitHub. |
| `pull access denied` on a Docker Image app | The image is private and no registry credential matches. Add one in **Settings -> Registries**. |

More in [Deploys and builds](/troubleshooting/deploys-and-builds).
