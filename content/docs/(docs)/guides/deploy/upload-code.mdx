Deploying an archive of your project instead of connecting a repository. Deplo builds it exactly
as it would build a clone, framework detection included, so it is the same pipeline: Railpack,
Nixpacks, a Dockerfile or a Static build.

Use it for a project that is not in Git, for a one-off, or when the code lives somewhere Deplo
cannot reach.

The archive is stored in the control plane's data directory, under
`uploads/<app id>/<upload id>/`, and the agent unpacks it on the server that builds it.

## Deploy one

<Steps>
<Step>

### Start a new app

**Add new**, then **Application**, then the **Upload** tile.

</Step>
<Step>

### Choose the archive

Drop it on the card, or click to browse. Accepted formats are `.tar.gz`, `.tgz`, `.tar` and
`.zip`. Include your project's root, so `package.json` or the equivalent sits at the top level, or
under the root directory you set.

<Image
  src={`${basePath}/screenshots/upload-code/01-wizard-upload.png`}
  alt="The Upload source step, where a zip or tarball is dropped"
  width={1728}
  height={1080}
  className="w-full rounded-lg"
/>

You can skip the first step entirely: drop the archive anywhere on the Overview and the wizard
opens here with the file already in hand.

</Step>
<Step>

### Deploy

**App name** is filled in from the filename; change it if you like. The server and the build
settings are under **Advanced**, and both already have an answer. Click **Deploy**: the wizard
uploads the archive and starts the first build straight after.

</Step>
</Steps>

To ship a new version, go to **Settings -> Deployments**, upload a new archive, and click **Save &
Deploy**. For an upload source that button does both.

## Good to know

- **No automatic deploys.** There is no repository to watch. You can still trigger a build from CI
  with a [deploy hook](/guides/releases/automatic-deployments), but the hook rebuilds whatever
  archive is currently stored.
- **Rollbacks still work.** Deplo builds this source, so past images are kept and a rollback
  re-runs one.
- **Exclude `node_modules` and build output.** They make the upload huge, and the build reinstalls
  dependencies anyway.
- **The archive replaces the previous one.** There is no upload history.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The build cannot find the project | The archive has an extra top-level directory. Set **Root directory** on the Deploy Source card, or repackage from inside the project. |
| The upload is rejected with `415` | The file is not one of `.tar.gz`, `.tgz`, `.tar`, `.zip`. |
| The upload is rejected with `413` | The archive is over the size limit. Exclude `node_modules` and build output. |
| The upload is rejected with `400` | The file is empty. |

More in [Deploys and builds](/troubleshooting/deploys-and-builds).
