<Callout type="warn" title="Dry run first">
Every command is a dry run unless you add `--yes`. **`--purge-data` is
irreversible**: it deletes Deplo's volumes, secrets and data on that host.
</Callout>

<Tabs items={['Uninstall an agent from the host', 'Uninstall Deplo itself']}>
  <Tab value="Uninstall an agent from the host">
    Use `--agent-only` for a server that should leave the control plane in
    `/opt/deplo` untouched. On the control-plane host it also removes
    Traefik, so the panel stops answering until you re-run `install.sh`.

    ```bash
    # See what would happen (dry run, the default)
    curl -fsSL https://<deplo>/uninstall.sh | sudo bash -s -- --agent-only

    # Do it
    curl -fsSL https://<deplo>/uninstall.sh | sudo bash -s -- --yes --agent-only

    # Do it, and delete the data too
    curl -fsSL https://<deplo>/uninstall.sh | sudo bash -s -- --yes --agent-only --purge-data
    ```
  </Tab>
  <Tab value="Uninstall Deplo itself">
    Without `--agent-only`, it removes the control plane in `/opt/deplo`,
    its Postgres and Traefik, as well as the agent and Deplo-managed
    containers.

    ```bash
    # See what would happen (dry run, the default)
    curl -fsSL https://<deplo>/uninstall.sh | sudo bash

    # Do it, keeping every volume and /opt/deplo
    curl -fsSL https://<deplo>/uninstall.sh | sudo bash -s -- --yes

    # Do it, and delete the data too
    curl -fsSL https://<deplo>/uninstall.sh | sudo bash -s -- --yes --purge-data

    # And the backups stored on this machine
    curl -fsSL https://<deplo>/uninstall.sh | sudo bash -s -- --yes --purge-data --purge-backups
    ```
  </Tab>
</Tabs>

<Callout title="When the instance itself is unreachable">
  If the panel or its DNS is unavailable, use `https://deplo.build/uninstall.sh`.
  It serves the newest script, so always read the dry run before adding
  `--yes` to an older installation.
</Callout>

## What it removes

By default, it removes the panel, Postgres, Traefik, agent, Deplo-managed
containers, the `deplo` network, and `/var/lib/deplo-agent`.

- `--agent-only` stops after removing the agent and host agent data.
- It never removes Docker Engine, rewrites `/etc/docker/daemon.json`, or
  touches containers without a Deplo label.
- It is safe to run on a host that was never a Deplo host and safe to run
  twice.

<Callout type="warn">
  **`--purge-data` deletes `/opt/deplo/.env`, and that holds
  `DEPLO_SECRET`.** Every backup artifact this instance wrote is encrypted
  with a key derived from it. Copy the file first if you may ever want to
  restore one.
</Callout>

The older `/uninstall-agent.sh` URL still works and applies
`--agent-only` automatically.
