A server installed as **Backups** has no Docker: to give it another role, re-run the install command
on the host. One moved from **Build** to **Everything** has no proxy until you do the same.

## Generated addresses

Every app gets a free address that needs no DNS, built from its server's address:

| Choice    | App address                                   | Points at       |
| --------- | --------------------------------------------- | --------------- |
| IPv4      | `web-calm-fox-cb00710a.deplo.site`            | `203.0.113.10`  |
| IPv6      | `web-calm-fox-v6-2001-db8--10.deplo.site`     | `2001:db8::10`  |
| Automatic | IPv4 when the server has one, IPv6 otherwise  |                 |

On the machine Deplo runs on, **Automatic** follows the installer's `--ipv4` or `--ipv6`.

Pick IPv6 when visitors reach the server over IPv6 only. Changing it renames every generated address on
the server, keeping its words: `web-calm-fox-cb00710a.deplo.site` becomes
`web-calm-fox-v6-2001-db8--10.deplo.site`. Each app answers on its new name after its next deploy.
Your own domains are not touched. A kind the server has no address for is greyed out.

## Removing a server

**Removing is trust revocation, not an uninstall.** Deplo forgets the server and never talks to it
again. It does not remove containers, because by then it may not be able to reach them. It prints a
one-line uninstall command to run on the host instead: see
[Remove or uninstall](/operations/remove-a-server-or-uninstall). The machine Deplo runs on can't be
removed.

## Before using maintenance

- **Health is a cache, not a gate.** Past a staleness window the page shows **Unknown** rather than a
  stale green. Deploys check the server live.
- **Changing the address moves nothing.** Generated addresses follow at once; your own domain keeps
  pointing at the old IP until you change its DNS record.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The server shows **Degraded** | The agent is up but Docker is not answering, or the server can't reach Deplo. Its tooltip says which. |
| A restart fails | The agent is unreachable. Health and **Check readiness** say so. |

More in [Servers and agents](/troubleshooting/servers-and-agents).
