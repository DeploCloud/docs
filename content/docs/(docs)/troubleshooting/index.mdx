## Check these first

1. **Open the relevant log.** Use the deployment's build log, the app's
   **Logs** tab, or a destination's **Connection log**.
2. **Check the server.** In **Settings -> Servers**, refresh the server and
   run **Check readiness** if the problem involves a deploy or container.
3. **Separate the app from its domain.** Try the generated
   `https://deplo-<hex>.nip.io` address. If it works, investigate DNS or the
   certificate. If it does not, investigate the app or server.

If it worked before, compare the last successful deploy with the failing one.
The change is usually a variable, dependency, Git credential, certificate, or
full disk.

## Statuses people often misread

| What you see | What it means |
| --- | --- |
| App **Error**, site still works | The last deploy failed; the previous stack is still serving |
| Preview is grey | It was evicted at the preview limit; redeploy it |
| Cron **skipped** | It did not start because the app was stopped or another run was active |
| Cron **lost** | The agent could not report the result; the command may have completed |
| Server **Unknown** | The health reading is stale; refresh the server |
| Readiness **skip** | Deplo could not evaluate that check; it is not a pass |

## If you still need help

Record the app, server, deploy timestamp, exact error, and the last successful
deploy. Use the feature guide's **Troubleshooting** section for context.

Report bugs in the issue tracker; report security issues using the project's
security policy.
