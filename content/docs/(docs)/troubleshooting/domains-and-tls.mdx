description: Fix DNS, certificate, routing, and panel access problems.

import { Globe, FileLock2, Server } from "lucide-react";

<Accordions>
<Accordion title="DNS is missing or points to the wrong server">

| State | Means | Fix |
| --- | --- | --- |
| `pending` | No record found at all | Create the A record the row prints |
| `misconfigured` | It resolves, but somewhere else | Point it at this app's server. The row prints the address |

Check it yourself:

```bash
dig +short app.example.com
```

No output means propagation or a typo. A different address means the record
still points to another host, proxy, or wildcard.

<Callout type="warn" title="The server matters">
An app running on server B needs its domain pointing at **B**, not at the
machine the panel runs on.
</Callout>

</Accordion>
<Accordion title="The browser shows a certificate warning">

Check these first:

1. **Port 80 is open.** Let's Encrypt validates over HTTP.
2. **DNS resolves from the server.** Fix the record, then **Reload** the app
   or redeploy.
3. **The domain is not `nip.io`.** Use a domain you own for a certificate.
4. **Certificate is set to Let's Encrypt.** Check the domain's **HTTPS** group,
   above **Advanced**.

</Accordion>
<Accordion title="A custom certificate is not being served">

- **It never loaded.** Check the intermediate chain and that the key matches.
  Otherwise the proxy serves its default certificate.
- **It is on the wrong server.** Certificates are per host. Add it to every
  server that runs the app.
- **The domain is set to None.** A domain with no certificate is on plain
  HTTP and will never pick one up.
- **It expired.** Nothing renews a custom certificate. The certificates page
  warns for the last three weeks.

</Accordion>
<Accordion title="The domain returns 404">

The request reached the proxy, but no route matched. Check:

| Check | Why |
| --- | --- |
| Is the app running? | A stopped app has no container to route to |
| Is the domain on the right app? | One hostname can route by path, but each path must match |
| Is DNS routable? | Only `valid` and `cloudflare` are routed |
| Is it the right server? | DNS decides which machine receives the request |
| For a Compose app, is **Container** set? | The router needs to know which service |

</Accordion>
<Accordion title="The domain redirects in a loop">

This is usually **Flexible** mode combined with an HTTPS redirect. Switch to
**Full** or **Full (strict)** and give the domain a real certificate here.

</Accordion>
<Accordion title="Two apps share a hostname">

`example.com/` and `example.com/api` may point at different apps. The longest
matching path wins.

If the wrong app answers, check **Internal path** and **Strip path before
forwarding** on both rows.

</Accordion>
<Accordion title="A hostname cannot be added">

**One hostname belongs to one team.** If another team already holds it, it
cannot be added here. The same applies to a preview base domain.

</Accordion>
<Accordion title="The panel is unreachable">

Try the generated `https://deplo-<hex>.nip.io` address. If it works, fix the
address in **Settings -> Deplo**. The browser warns about its certificate once.

If that is silent too, the proxy is down. From the server itself:

```bash
curl http://127.0.0.1:3000/api/health   # the panel, past the proxy
docker ps
docker logs deplo-traefik
docker logs deplo-deplo-1
```

If the proxy is down, tunnel to the panel:

```bash
ssh -L 3000:localhost:3000 root@<server-ip>   # then open http://localhost:3000
```

</Accordion>
</Accordions>
