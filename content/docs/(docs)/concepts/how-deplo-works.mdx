Deplo is two programs with one rule between them.

## The two parts

- **The control plane decides.** It is the dashboard you log into. It stores the data, signs
  people in, prepares the Compose file and the routing rules, and decrypts the environment
  variables. Then it hands the result to a server.
- **The server agent executes.** One small program per server, `deplo-agent`. It is the only
  thing that runs Docker, touches the filesystem or opens a shell: builds, deploys, logs, the
  console, metrics, backups, restores and disk cleanup all go through it.

<PartsDiagram />

## The rule

**The control plane never touches Docker or a server directly.** Every action goes through the
agent, over mutual TLS, with the agent's certificate pinned when the server joins.

- **The machine running Deplo is a normal server.** It runs the agent like every other one.
- **An offline server is an error.** Every deploy starts by contacting the agent. If it does not
  answer, the deploy fails and says so; nothing runs on the control plane instead.
- **The control plane never gets the Docker socket.** It is the part reachable from the internet.
  Traefik reads container labels through a read-only proxy instead.

## What Traefik does

One reverse proxy per server, the `deplo-traefik` container, on ports `80` and `443`. Every
hostname you add becomes a route: rule, entry point, certificate provider, and extras such as
basic auth, path stripping and redirects. Traefik renews Let's Encrypt certificates itself, and
Deplo edits its configuration in place, so changes made by hand survive.

## Where the data lives

- **Postgres holds all control plane data:** apps, teams, domains, deployment history, encrypted
  secrets and activity.
- **Your application data lives on the servers**, in Docker volumes the agent manages. It only
  crosses the control plane encrypted, in transit between two servers (a backup sent to another
  server, an app moved to another server), and is never stored there.

## How secrets move

Secrets are encrypted at rest with a key derived from `DEPLO_SECRET`. A secret variable is
**write-only**: nothing returns it, and changing one means deleting and adding it again. A few
other values can be shown again, each behind a capability:

| Value | Capability |
| --- | --- |
| A managed database's connection string | `reveal_secrets` |
| A backup destination's recovery key | `reveal_secrets` |
| A basic-auth password | `manage_basic_auth` |
| An app's deploy hook URL | `configure_apps` |

**The agent never holds the encryption key.** The control plane decrypts at deploy time and
sends the values inside the encrypted connection.

## What this means day to day

| If you see | It is because |
| --- | --- |
| A server shows **warning** | The agent answers, but Docker does not, so nothing can deploy. |
| The rendered Compose file shows `••••••••` | Environment values, commands and secrets are masked. |
| Two apps reach each other by name | They share an Environment, and so its network. Apps in different Environments cannot, even on one server. |
