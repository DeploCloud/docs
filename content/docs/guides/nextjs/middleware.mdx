---
title: Middleware
description: Edge runtime constraints for Next.js middleware on Deplo.
---

`middleware.ts` runs on Deplo's edge network, on every matching request,
before it reaches a route handler or page.

<Callout type="warning" title="Middleware limits">
  Middleware has the same constraints as the Next.js Edge runtime: no
  filesystem access, and a 1MB code size limit after bundling.
</Callout>

## What works

<TypeTable
  type={{
    "Request rewrites / redirects": {
      description: "NextResponse.rewrite / redirect",
      type: "supported",
    },
    "Reading cookies and headers": {
      description: "via NextRequest",
      type: "supported",
    },
    "Setting response headers": {
      description: "via NextResponse",
      type: "supported",
    },
    "fetch() calls": {
      description: "outbound requests to your own APIs or third parties",
      type: "supported",
    },
  }}
/>

## What doesn't

<Callout type="error" title="Not supported in middleware">
  Node.js-only APIs (`fs`, `net`, native addons) and any dependency that
  isn't Edge-compatible will fail to bundle. Move that logic into a route
  handler instead, those run in the full Node runtime.
</Callout>
