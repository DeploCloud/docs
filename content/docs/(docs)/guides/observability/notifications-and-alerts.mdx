Get told when something happens: a deploy failed, a backup did not run, a server went offline,
somebody created an API token.

- **A channel** is where a message goes. Twelve kinds, as many of each as you like.
- **Each channel has its own alert selection.** A team chat room can get every deploy result
  while an on-call phone gets only failures. A new channel starts with sensible defaults.

Notifications are per team: another team's failures go to its own channels. The capability is
`manage_notifications`.

**Settings -> Notifications -> Add channel.**

| Kind | What it needs |
| --- | --- |
| **Discord**, **Webhook** | A webhook URL |
| **Slack**, **Mattermost**, **Lark** (beta) | An incoming webhook URL |
| **Microsoft Teams** (beta) | A Power Automate workflow URL |
| **Telegram** (beta) | A bot token and a chat id |
| **Email** | A recipient, a from address, and your SMTP server or a Resend API key |
| **ntfy** (beta) | A server URL (`https://ntfy.sh` or your own), a topic, and a token for a protected topic |
| **Gotify** (beta) | Your server URL and an application token |
| **Pushover** (beta) | An application token and a user or group key |
| **Browser push** | Nothing: turning it on asks the browser for permission, once per device |

Save, then **Send a test**. Secrets are write-only: a field left blank keeps what is stored.

**Every URL must be public HTTPS, and the SMTP host public too.** Private and internal addresses
are refused, so a Gotify or ntfy on your LAN does not work.

## Alerts on your phone

Browser push needs the panel on HTTPS. On a phone, install Deplo first:

<Steps>
<Step>

### Install Deplo

Open Deplo in the phone's browser, tap **More** in the tab bar, then **Install Deplo** under
**This phone**. On an iPhone: Safari's **Share** button, **Add to Home Screen**, then open Deplo
from the home screen.

</Step>
<Step>

### Turn on Notifications on this phone

Same place: **More -> This phone -> Notifications on this phone**. It covers the team you are in.

</Step>
</Steps>

- **The first device creates the team's Browser push channel** with the default alerts. That
  takes `manage_notifications`; without it the row reads **Ask an admin to turn on phone alerts**.
- **Every member turns it on per device**, up to 10 browsers each. A member limited to some apps
  only gets alerts about those.
- **Turned off in Notifications settings** means the channel exists but is off.

## Pick what each channel is told about

Open the channel and use its alert picker: a search box, a category list, **Reset to defaults**
and **Unselect all**. The 47 alerts:

| Category | Alerts |
| --- | --- |
| **Deployments** | Deployment failed, Deployment succeeded, Deployment interrupted, Git connection stopped working, Git provider is missing access |
| **Apps** | App keeps restarting, [App stopped answering, App still not answering](/guides/observability/health-checks#when-an-app-stops-answering), [Apps waiting for room after a failover](/operations/clusters/failover#waiting-for-room), [Server back in its cluster](/operations/clusters/failover#when-a-server-comes-back), App ran out of memory, [Security update available](/guides/observability/security-updates#alerts) |
| **Cron jobs** | Cron job failed, Cron job finished, [Cron job lost with its server](/operations/clusters/logs-metrics-and-previews#cron-jobs) |
| **Databases** | Database ready, Database setup failed, Database rebuilt, Database deleted |
| **Backups & restore** | Backup failed, Backup finished, Restore finished, Restore failed |
| **Servers** | Server offline, Server back online, Server cannot run apps, Server identity changed, Server unusable until it updates, Server running hot, Server disk almost full, Server agent certificate not renewed, Cleanup failed, Leftover containers |
| **This Deplo instance** | Deplo update available, Deplo security fix, [Deplo updated itself](/operations/update#automatic-updates), [Automatic update stopped](/operations/update#automatic-updates) |
| **Security & team** | Member joined, Member removed, Member access changed, API token created, API token revoked, Two-factor requirement changed, Team owner changed, Repeated failed sign-ins |
| **Domains & TLS** | Certificate expiring, Domain points elsewhere |

**This Deplo instance** alerts reach every team. **Deplo security fix** repeats every 3 days
until the instance is [updated](/operations/update#when-a-new-version-is-out), **Deplo update
available** every week.

A condition that lasts is announced once, then again only after a cooldown: 30 minutes for most,
an hour for **Server running hot** and **Server disk almost full**.

## Alerts are not the activity trail

- **An alert interrupts.** It goes to a channel right away, because somebody should look.
- **[Activity](/guides/team/activity) is looked up later**: who did what, and when. It is never
  delivered anywhere.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The test works, real alerts never arrive | The channel's alert selection does not include them, or it reads **No alerts picked**. |
| **Needs setup** on a channel | A required field is empty. Open it and fill it in. |
| The test fails | The message names the cause: a rejected certificate, a refused connection, a name that does not resolve. |
| Saving is refused | The URL is not public HTTPS, or it resolves to a private address. |
| Email never arrives | Check the SMTP host, port and credentials, and whether your provider needs a verified sender. |
