Every app starts from one of five sources. Pick the one that matches what you already have, or let
a template fill all of it in.

| Source | What it needs | Builds an image | Rollback |
| --- | --- | --- | --- |
| [GitHub](/guides/deploy/from-git) | A repository, connected once per team | yes | yes |
| [Git](/guides/deploy/from-git) (beta) | GitLab, Bitbucket, Gitea or any git server | yes | yes |
| [Docker image](/guides/deploy/docker-image) | An image reference | no, already built | no |
| [Upload](/guides/deploy/upload-code) | A compressed archive of the project | yes | yes |
| [Compose](/advanced/compose-apps) | A `docker-compose.yml`, brought up as written | no | no |

## Or start from a template

A [template](/guides/deploy/from-template) is not a sixth source: it is a Compose stack the
catalogue already wrote, with its passwords generated and its address picked. Deplo creates an
ordinary Compose app out of it, and nothing links the app back to the template afterwards.

Reach the catalogue from **Templates** in the sidebar, or from the **Template** button under the
five tiles on the first step of the new-app wizard - that button leaves the wizard for the
catalogue rather than being a source of its own.
