Every build leaves an image on the server. A rollback runs that image again, so it takes seconds
and rebuilds nothing. It needs the `rollback_apps` capability.

- **No rebuild.** No clone, no dependency install, no waiting.
- **Only the code goes back.** Variables, domains, volumes and resource limits come from your
  **current** settings.
- **It is a normal deployment.** It has its own row, logs and activity entry, marked as a
  rollback, and it does not use a retention slot.

Deplo refuses a rollback when the target ran on a **different server**, belongs to a
**preview**, or **is itself a rollback**. The message says which.

## Retention

<Image
  src={`${basePath}/screenshots/rollbacks/03-retention.png`}
  alt="Keep rollbacks, the number of old deployments kept ready to go back to"
  width={1728}
  height={1080}
  className="w-full rounded-lg"
/>

**Settings -> Deployments**, the **Rollbacks** card, field **Keep**.

| | |
| --- | --- |
| Default | `3` |
| Maximum | `20` |
| `0` | Hides the action for this app |

The server keeps `Keep + 1` images per app. Older ones are removed by the server's disk cleanup
after a deploy. Kept images share layers, but they still use disk.

Once an image is removed from the server, that deployment can no longer be rolled back to, even
if its row is still in the list.

## Good to know

- **Only sources Deplo builds can roll back.** A Docker image app and a Compose app do not have
  the action.
- **A rolled-back app still auto-deploys.** The next push replaces it. Turn off **Deploy on
  push** first if the branch is broken.
- **A database migration does not roll back with the code.** Your data stays as it is.
- **Rolling back does not stop the app.** Use **Stop** for that.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The **Rollback** action is missing | The source is a Docker image or a Compose app, **Keep** is `0`, or you do not have `rollback_apps`. |
| Rollback is refused on a deployment | It ran on another server, it is a preview, or it is itself a rollback. |
| Rollback fails with an image not found | It was removed. Raise **Keep**, or exclude that server from unused-image cleanup. |
| The bug is still there after the rollback | The bug is in configuration or data, not in the code. |

More in [Deploys and builds](/troubleshooting/deploys-and-builds).
