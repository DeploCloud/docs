---
title: install-agent.sh
description: Brings one more server into the fleet, verifies its checksum and enrolls it over mutual TLS.
---

```bash
curl -fsSL https://<deplo>/install-agent.sh | sudo bash -s -- <TOKEN> <URL> [FINGERPRINT]
```

The three role flags below pick what the server is for, see
[Server roles](/advanced/server-roles) for the full comparison.

<Callout type="warn" title="Always take this command from the dashboard">
  The copy in the repository has placeholders that the running instance
  substitutes with the release's per-architecture URL and its checksum,
  and it refuses to run unsubstituted.
</Callout>

<Callout type="info" title="Requires">
  Root, `systemd`, `curl` and `sha256sum`, on `linux/amd64` or `arm64`.
  Docker is installed if missing, except for a migration source, which
  needs the Docker it imports from. It refuses below **5 GB free on `/`**,
  recommends 30 GB, and checks nothing about memory or CPU.
</Callout>

## What the installer does

- Runs a preflight for the architecture, required tools, disk space and
  control-plane URL. `--force` overrides only the 5 GB disk check.
- Installs Docker, address pools, `git`, and Traefik when the selected role
  needs them.
- Downloads the `amd64` or `arm64` agent and verifies its SHA-256 checksum.
- Installs the agent and systemd unit, then starts the service.
- Enrolls over mTLS. It stores bootstrap credentials in
  `/var/lib/deplo-agent/bootstrap.env` with mode `0600` and clears old
  certificates on reinstall.

The installer never changes the firewall. If `ufw` or `firewalld` blocks
`9443`, it prints the command needed to open it.

Flags: `--check` runs the preflight and exits, `--force` overrides the disk floor, and `--plain`,
`--no-color`, `--quiet` and `--help` do what they say.

The agent then calls home, sends a certificate signing request, and
receives a signed certificate. **The control plane never connects to your
machine to set this up.**

Logs: `journalctl -u deplo-agent -f`.
