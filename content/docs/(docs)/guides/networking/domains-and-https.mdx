This page covers every address an app answers on: your own hostnames,
certificates, path-based routing and redirects. For one domain with HTTPS,
[Add a domain](/getting-started/add-a-domain) is the short version.

A domain is **one row: hostname plus path**. On every deploy Deplo turns each
row into a proxy route with its certificate, middlewares, target container and
port.

**A path route always wins over a whole-host route**, longest path first. This
is what lets `example.com/api` and `example.com/` go to two different apps.

Deplo checks DNS itself, on a schedule and on demand. A hostname is routed only
when the check passes.

## Add and manage domains

Open the app, then **Domains**. **Add Domain** opens the dialog. **Add domain**
confirms, and **Generate** creates a free `deplo.site` hostname. Each row has four
buttons: re-check DNS, **Set as primary**, edit, and **Remove domain**.

Exactly one domain is primary. It is the URL shown in the app header, in
notifications, and everywhere Deplo names the app's address.

## DNS states

| State | What it means | Routed |
| --- | --- | --- |
| `valid` | The hostname resolves to this app's server | yes |
| `cloudflare` | Proxied through Cloudflare, so the real origin cannot be checked. The row gets a **Cloudflare DNS** badge | yes |
| `pending` | No record found yet. The row shows the exact A record to create | no |
| `misconfigured` | It resolves, but to a different address. The row shows the address it should point at | no |
| `error` | The lookup itself failed | no |

For a CDN or proxy Deplo does not recognise, turn on **Behind a proxy** under
**Advanced settings -> Proxy**.

## Certificates

The **Certificate** field is in the **HTTPS** group, above **Advanced
settings**. Picking a provider is how a domain gets HTTPS. There is no separate
switch.

<Callout type="warn" title="Cloudflare Flexible mode">

**Full** or **Full (strict)** with a certificate on this side.

Example, **two apps on one domain**:

- `example.com/api` goes to the API app, with internal path `/api` and strip
  path on. The API container receives `/users` instead of `/api/users`.
- `example.com/` goes to the web app, with no internal path.

## Redirects

The **www redirect** field, under **Advanced settings**, redirects
`www.example.com` to `example.com`, or the other way round. It only offers that
pair, and is hidden when the hostname has no www or apex counterpart.

The redirecting hostname is a normal domain row with its own DNS check and its
own certificate. The primary flag stays on the hostname that serves the app.

## Good to know

- **A `deplo.site` hostname can never hold a certificate.**
- **50 Let's Encrypt domains per team.** Open pull request previews with a
  Let's Encrypt hostname count too. Domains with no certificate do not.
- **Port 80 must be open even for an HTTPS-only site.** The certificate
  validation happens there.
- **A hostname belongs to one team.** Another team cannot add it. The same
  applies to a preview base domain.
- **The same hostname on two paths can belong to two apps in your team.**
- **Changing a domain applies on the next deploy or a Reload.** Use **Reload**
  on the app to re-apply routing without rebuilding.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Stuck on `pending` | No A record yet. The row shows the exact record to create. |
| `misconfigured` | It resolves somewhere else. An old record, or a proxy in front. |
| Certificate warning in the browser | The certificate never issued. Port 80 closed, or DNS pointing elsewhere. |
| 404 from the proxy | Nothing matches the rule: the app is stopped, or the domain belongs to an app on a different server. |
| A redirect loop | Cloudflare Flexible mode plus an HTTPS redirect on this side. Switch Cloudflare to Full. |

More in [Domains and TLS](/troubleshooting/domains-and-tls).
