## What it is

Moving it is a real operation with real consequences, which is why it has its own page.

**Settings -> Deplo**, instance admins only.

---

## How it works

The panel is routed by the host's Traefik like anything else, but through a **file provider** entry rather than container labels. That's deliberate: a panel published by labels could never change its own route, because changing it would need the panel.

The address is also used for more than serving pages:

- It is baked into the **install command** printed for new servers.
- It is where **git provider webhooks** deliver.
- It is the **origin passkeys are bound to**.
- It sets the cookie `secure` flag.

---

## Change the address

<Steps>
<Step>
### Point DNS at this server
Point the new hostname's DNS at this server first. The page shows the exact record.
</Step>

<Step>
### Open the panel address setting
**Settings -> Deplo**, find **Panel address**, click **Change address**.
</Step>

<Step>
### Enter the new address
An impact check runs and tells you what it found: an IP address rather than
a hostname, missing HTTPS, or a DNS record that does not resolve here yet.
</Step>

<Step>
### Turn on HTTPS
Use **Serve the panel over HTTPS** once the hostname resolves, so Traefik can get a certificate for it.
</Step>

<Step>
### Save
</Step>
</Steps>

<Callout type="info">
`http://<server-ip>:3000` keeps working throughout. See
[ports, networks, and files](/reference/ports-networks-and-files).
</Callout>

## The certificate account email

**Certificate account email**, on the same page, is the address Let's Encrypt has on file for this instance's ACME account. It is where expiry warnings go.

---

## Limits and gotchas

<Callout type="warn">
- **Every passkey breaks when the address changes.** They are bound to a hostname by the standard. They show **Not usable here**, the password still signs people in, and everyone re-registers a passkey on the new address. Warn your team before you do this.
- **Webhooks must be re-pointed.** Deplo re-registers what it can, but a provider that cannot reach the new address stops delivering, and pushes stop deploying.
- **The install command changes.** Servers already enrolled are unaffected, new ones use the new address.
- **Do not use an IP for the panel address** unless you accept no certificate. Let's Encrypt does not issue for bare IPs.
- **`DEPLO_PUBLIC_URL` in `/opt/deplo/.env` is the other half.** If you edit the environment by hand, keep them consistent.
</Callout>

## If it does not work

<Callout type="error" title="If it does not work">
A certificate warning on the new address, a panel unreachable after the
change, or "No server accepted the change": see
[Domains and TLS troubleshooting](/troubleshooting/domains-and-tls).
</Callout>
