## A server is stuck provisioning

**Provisioning** means its agent has never called home. On the machine:

```bash
systemctl status deplo-agent
journalctl -u deplo-agent -f
```

| What you see | Fix |
| --- | --- |
| No `deplo-agent` unit | The install command never ran, or failed early. Run it again |
| `Refusing to run an unverified binary` while installing | The download did not match its checksum. Retry; if it persists, something intercepts the download |
| `bootstrap token has already been used`, `has expired` or `is not recognised` | The token is single-use and lasts one hour. [Reissue the install command](#a-server-agent-needs-to-be-reinstalled) and run the new one |
| `status=216/GROUP` | The unit needs the `docker` group and Docker is gone. Run the install command again. A server that only holds backups is added as **Backups only** |
| The unit runs, nothing happens | It cannot reach the panel. Check the machine's internet access and the address in the command |

## A server is offline

Deplo never calls a server: its agent connects out to Deplo, so there is no port to open.
**Offline** means it has not been connected for about 10 seconds. It comes back by itself within
seconds of reaching Deplo again, and its apps keep running meanwhile.

| Its card says | Fix |
| --- | --- |
| `Check that the machine is on and connected to the internet.` | Start or reconnect the machine. Still offline: `journalctl -u deplo-agent -f` says why it cannot reach Deplo |
| `This server can't reach Deplo at deplo.example.com.` | See [A server hasn't connected to Deplo yet](#a-server-hasnt-connected-to-deplo-yet) |
| `This server can't be used until its server agent is reinstalled.` | See [A server agent needs to be reinstalled](#a-server-agent-needs-to-be-reinstalled) |

## A server was off while the panel's address changed

A connected server learns the new address at once. One that was off reconnects through the
panel's backup address, like `deplo-cb00710a.deplo.site`.

If that is gone too (turned off, or the panel had no domain and its generated address changed),
[reinstall its server agent](#a-server-agent-needs-to-be-reinstalled). A panel domain with the
backup address left on avoids this.

## A server hasn't connected to Deplo yet

It enrolled but never connected since, so it is **unusable**. Its apps keep running.

- Card: `This server can't reach Deplo at deplo.example.com. Check that it's connected to the internet.`
- Its page: `Unusable - it hasn't connected to Deplo yet`. Banner: `edge-2 hasn't connected to Deplo yet.`

Nothing needs reinstalling: it connects as soon as it can reach `https://deplo.example.com` the way
a browser would.

- **The machine is off or has no internet**: start it or reconnect it.
- **Its network only lets some sites through**: allow `https://deplo.example.com`. A company proxy
  or an outbound firewall rule is the usual cause.
- **Still can't reach Deplo**: on the server, `systemctl status deplo-agent`, then
  `journalctl -u deplo-agent -f` says why.

A server you no longer use can be [removed](/operations/remove-a-server-or-uninstall) instead.

## A server was left behind

An instance admin [left it behind](/operations/update#leave-a-server-behind) at the v0.6.0 update
stop. Past that update it is **unusable**, with its apps still running. Its page says which way back:

- `Unusable - reinstall its server agent`: [reinstall it](#a-server-agent-needs-to-be-reinstalled).
- `Unusable - it hasn't connected to Deplo yet`: it can still [connect by itself](#a-server-hasnt-connected-to-deplo-yet).

## A server says Degraded, Error, or Unknown

| Chip | Means | Fix |
| --- | --- | --- |
| **Degraded** | `The agent is up but Docker is unreachable` | `systemctl status docker` on the host |
| **Error** | The agent's certificate is untrusted or expired, it speaks an unsupported protocol, or it answered with an error. The tooltip says which | Reissue the install command and run it; for a protocol error, update the agent |
| **Unknown** | The stored reading is stale | **Refresh** on the Servers list |

Health is a stored reading, while a deploy does a live handshake: a green chip and a failing deploy
can happen together.

## Check readiness instead of guessing

**Check readiness** on the server's **Overview** tab runs one live check of the agent, Docker,
routing, capacity, build methods and Deplo configuration. A failed check blocks deploys, a warning
means it deploys but is not fully usable, and **skipped** means it could not be evaluated, not that
it passed.

## Metrics show dashes

The telemetry stream is not connected: refresh the server first. Chart history lives in the panel's
memory, so it starts empty after a panel restart, and on every reload when **Save metrics on
server** is off.

## A deploy says the server has run out of Docker networks

`This server has run out of Docker networks (the default is about 31).` Every Environment and every
preview has its own network.

- The installer wrote a wider address pool but printed `Docker is running 3 container(s), so it was NOT restarted`:
  run `systemctl restart docker` in a maintenance window.
- Otherwise reclaim **Leftover networks** in the server's **Cleanup** tab.

## A deploy fails with No chain DOCKER-FORWARD

Docker's forwarding chains were removed underneath it. Restart Docker to recreate them.

## A removed container still appears

Deplo retries an unconfirmed teardown and raises a **Leftover containers** alert if it gives up.
Removing the server drops its pending teardowns.

## The install command returns 503

`Deplo could not resolve the agent's binary`: the panel cannot reach `github.com` to fetch the
agent release and its checksums. Restore outbound access from the panel's machine, then run the
command again.

## The install command contains 127.0.0.1

Deplo generates that address only for the machine running the panel. Run it there; every other
server gets a command with the panel's public address.

## A server agent needs to be reinstalled

Its agent is older than `0.5.1-canary.10`, too old to connect, or it was
[left behind](#a-server-was-left-behind). Nothing Deplo does can reach it.

- Card: **Offline**, `This server can't be used until its server agent is reinstalled. An instance admin can do it from the server's Advanced tab.`
- Its page: `Unusable - reinstall its server agent`, with no **Retry now**. Banner: `edge-2 is unusable until its server agent is reinstalled.`

An instance admin reinstalls it:

1. **Settings -> Servers -> the server -> Advanced -> Install command**.
2. **Reissue install command**, then run the command it shows on the server.

It comes back as it was, with its apps. Always reissue first: the installer clears the old
certificates, and an old token is rejected.

## A server is permanently gone

Remove it in Deplo. That revokes its trust and does not need the machine to answer. See
[Remove or uninstall](/operations/remove-a-server-or-uninstall).
