server you pick, never on the control plane.

<Tabs items={['GitHub', 'Git', 'Docker Image', 'Compose', 'Upload']}>
<Tab value="GitHub">

No GitHub App connected yet? Click **Connect GitHub** and follow GitHub's screens: Deplo creates
the App for you. Choose the repositories it may see, then pick one and its branch. See
[GitHub](/guides/git-providers/github).

</Tab>
<Tab value="Git">

Pick the provider, paste the repository URL, set the branch. See
[Git connections](/guides/git-providers/git-connections) for GitLab, Bitbucket and Gitea.

</Tab>
<Tab value="Docker Image">

Type the image, like `ghcr.io/acme/api:v2.3.1`. It autocompletes from public and private
registries. The name and port come from the image. Nothing is built: the server only pulls it.
See [Deploy a Docker image](/guides/deploy/docker-image).

</Tab>
<Tab value="Compose">

Click **Write compose** and paste your `docker-compose.yml`. The editor checks it as you type: what
it rewrites, what needs a permission, what it refuses. See [Compose apps](/advanced/compose-apps).

</Tab>
<Tab value="Upload">

Drop a compressed archive of your project, or click to browse. It is built like a Git clone,
framework detection included. See [Upload your code](/guides/deploy/upload-code).

</Tab>
</Tabs>

Docker Image, Compose and Upload deploy from this card: skip to **Deploy**.

</Step>
<Step>

### Set up the app

**GitHub and Git only.** Deplo has read the repository and filled this card in:

- **App name**, from the repository.
- The framework it found, and the container port that framework uses.
- **Build command** and **Deploy command**, from your `package.json`, for your package manager.
  **Reset** empties a field and lets the builder decide.
- **Automatic deployments**, on: every push to that branch deploys.

</Step>
<Step>

### Deploy

Click **Deploy**. Server, URL and build method are already set. Deplo builds your `Dockerfile` if
there is one, else your Compose file, else it detects the framework and builds with
**Railpack**: you need neither file.

You land on the live build log. Closing the tab or reloading does not cancel anything.

</Step>
</Steps>

## What is under Advanced

Every card with a **Deploy** button has an **Advanced** drawer, labelled with the target server.

| Setting | What it is |
| --- | --- |
| Deploy to | The server that runs it. A single-machine install has one, already picked. |
| Environment variables | Type them, or tick [shared variables](/guides/config/shared-variables). Both reach the first build. |
| Build method | **Automatic** (the default), **Dockerfile** or **Compose**; **Always build with Railpack** skips your files. Plus the Node.js version and container port. |
| Port | Docker images only: the port routing uses, read from the image. |
| Build path | The sub-folder to build from, for a monorepo. |
| Build on | Another server to build on. **Automatic** uses a [build server](/advanced/build-servers) if you have one. |
| Git | Deploy on push or on tag, watch paths, submodules. |
| Extra compose flags | Compose stacks only: appended to `docker compose up`. |

## What you get

When the badge in the app header reads **Online**, the header shows the production URL and a
**Visit** button. A few seconds later the Overview shows a picture of the site.

That first URL is a free `deplo.site` hostname that points at your server with no DNS to set up.
On a server with a public IP it gets a Let's Encrypt certificate, so it is HTTPS from the start.
[Add a domain](/getting-started/add-a-domain) for your own hostname.

## The tabs you now have

**Overview** (production deployment, last four builds, URL), **Deployments** (every build, with
**Redeploy**, **Rollback** and **Delete**), **Domains**, **Environment**, **Logs**, **Monitoring**,
**Backups**, **Activity** and **Settings**. **Console**, **Cron jobs** and **Pull requests** appear
once you turn them on.

## Good to know

- **The slug is permanent.** The display name can change; the slug in URLs and volume names
  cannot.
- **The first build is the slow one.** Later ones reuse the server's build cache.
- **A private repository needs a connection, not a key in the URL.** Connect the provider once in
  **Settings -> Git** and every app reuses it.
- **A private image needs credentials in Settings -> Registries**, not in the image reference.
- **`Error` means the last deploy failed, not that the app is down.** See
  [App status](/concepts/apps-projects-and-environments#app-status-is-intent-not-observation).

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The build fails on a missing command | Your repository has no `build` or `start` script, so the builder guessed. Set both in the app's **Settings -> Deployments**. |
| The deploy fails after the build | The app did not start and stay up; the log says why and shows its last lines. Listen on `0.0.0.0`, not `127.0.0.1`. A wrong [port](/guides/releases/build-settings#the-port-is-the-one-people-get-wrong) is fixed for you. |
| The repository picker is empty | The GitHub App cannot see it. Click **Manage connected apps** and grant it on GitHub. |
| `pull access denied` on a Docker Image app | The image is private and no registry credential matches. Add one in **Settings -> Registries**. |

More in [Deploys and builds](/troubleshooting/deploys-and-builds).
