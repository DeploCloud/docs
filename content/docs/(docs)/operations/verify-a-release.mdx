Every Deplo image on `ghcr.io/deplocloud/deplo` is signed by Deplo's release workflow, with
[Sigstore](https://www.sigstore.dev/) and a short-lived certificate, not a long-lived key. Checking
it is optional, and proves the exact image came from that workflow.

<Callout type="info">
  Releases built from 31 August 2026 onward carry an attestation. Older tags report that none was found.
</Callout>

## Verify the image

<Steps>
<Step>
### Install the GitHub CLI
[GitHub CLI](https://cli.github.com/) **2.49 or newer**, on any machine that can reach the registry.
</Step>

<Step>
### Run the check
With the version you are about to install:

```bash
gh attestation verify oci://ghcr.io/deplocloud/deplo:0.8.1 --repo DeploCloud/deplo
```
</Step>

<Step>
### Read the result
A good result names the checked digest:

```
Loaded digest sha256:<digest> for oci://ghcr.io/deplocloud/deplo:0.8.1
Verification succeeded!
```

Anything else is a failure.
</Step>
</Steps>

## The server agent

Nothing to do by hand. `install-agent.sh` and every automatic agent update check the binary against
its published SHA-256 and refuse to run it on a mismatch.

## If verification fails

**Do not run the image.** It is not the one Deplo published, or the tag now points elsewhere.

- Re-run the check against a digest rather than a tag, in case a mirror or proxy serves something stale.
- Pull again from `ghcr.io` directly.
- Still failing? Report it privately through
  [Deplo's security policy](https://github.com/DeploCloud/deplo/blob/main/SECURITY.md), never in a public issue.
