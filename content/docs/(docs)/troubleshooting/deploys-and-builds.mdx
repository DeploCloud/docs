## The build fails

**Read the build log first.** Use the last error line to choose the fix. For a Railpack build,
that line usually says what to change.

| In the log | Cause | Fix |
| --- | --- | --- |
| `No start command detected` | Railpack found nothing to start | Set **Start command** on the **Build & output** card in **Settings -> Deployments** |
| `Railpack does not recognise this folder` | The app is not in the folder the build looks at | Set **Root Directory**, or add a `Dockerfile` |
| `is not available` | Your project asks for a language version that does not exist | Pin a released one: **Node.js version** for Node, a variable such as `RAILPACK_PYTHON_VERSION` for the others |
| `A native module failed to compile under Node 24` | A dependency does not build on Node 24 yet | Set **Node.js version** to `22` |
| `The build needed more than 2.9 GB of memory` | One build step went past 75% of the server's memory | Build on a server with more memory, for example a [build server](/advanced/build-servers) |
| `GitHub refused a download with its rate limit` | Railpack's tool downloads hit GitHub's limit for anonymous requests | Connect the [GitHub App](/guides/git-providers/github) to the team, or deploy again in an hour |
| `command not found` | Detection chose the wrong command, or a dependency is missing | Set **Build command** in **Settings -> Deployments**, or add the dependency |
| `Cannot find module` | The build ran in the wrong directory | Set **Root Directory** |
| `pull access denied` | A private image with no matching credential | Add the registry in **Settings -> Registries** |
| `Authentication failed` while cloning | The Git credential expired or was revoked | **Settings -> Git**, then **Test connection** |
| `no space left on device` | The server's disk is full | See "No space left on device" below |

Detection runs on every deploy. If it changed after a repository change, set
the commands explicitly; explicit settings win.

## The build passes but the deploy fails

After the build, Deplo waits up to 3 minutes for the app to start and stay up. The log names what
went wrong and shows the app's last lines.

| In the log | Fix |
| --- | --- |
| `keeps restarting` or `stopped right after it started` | The app crashes on start. Read its last lines: a missing variable or a database it cannot reach are the usual causes |
| `The start command runs a program that is not in the image` | Fix **Start command** in **Settings -> Deployments** |
| `listens only on 127.0.0.1` | Make the app listen on `0.0.0.0` |
| `never listened on port 3000` | The app opened no port. Check that it starts a web server. A background worker needs no domain, and without one it only has to stay up |
| `was stopped: out of memory` | Give it more memory in [Resource limits](/advanced/resource-limits) |
| `health check fails` | Check the [health check](/guides/observability/health-checks) path and port |

A wrong port is not on this list: Deplo moves the traffic to the port the app listens on and says
so in the log. See [the port](/guides/releases/build-settings#the-port-is-the-one-people-get-wrong).

## The build passes but the app is unreachable

Check these in order:

1. **Domain state:** only a routable domain can reach the app. See
   [Domains and TLS](/troubleshooting/domains-and-tls).
2. **Container status:** read the app's **Logs** if it stopped after the deploy.
3. **A port set on one hostname** in **Domains** must be one the app listens on.

Use the generated address (like `https://deplo-cb00710a.deplo.site`) to separate an app
problem from a DNS or certificate problem.

## The app restarts, is unhealthy, or has no container

Open the app's **Logs** tab and look at the runtime notice:

- **Restarting:** the process starts and exits repeatedly. Check its command,
  required variables, and the last log lines.
- **Unhealthy:** the container is running but its healthcheck fails. Check the
  path, port, command, and whether `curl` or `wget` exists in the image.
- **Degraded:** a Compose service is missing or stopped. Check the service
  named in the notice and its logs.
- **Not running:** the app is deployed but no container is running. The logs
  usually show why it exited.
- **Stopped after 10 restarts:** restart loop protection stopped the container
  because it kept crashing. Fix what the logs show, then press **Start**. See
  [Logs](/guides/observability/logs).

After changing variables, the healthcheck, or storage, **Redeploy**. Use
**Rebuild container** only when the rendered stack must be recreated.

## A push does not start a deploy

| Check | Where |
| --- | --- |
| Is **Deploy on push** on? | **Settings -> Deployments** |
| Is the webhook healthy? | Same page. A red state means the provider cannot reach this instance |
| Is it the branch the app tracks? | **Deploy source** |
| Do **Watch paths** exclude what you pushed? | Same page. Empty means deploy on anything |
| Is it a bare Git URL? | Then there is no webhook at all. Use the [deploy hook](/guides/releases/automatic-deployments) |

If the panel address changed, update the webhook or use a new deploy hook.

## A deploy is stuck in the queue

Deploys to one server run one at a time by default. Check the build log and
the target server:

- Another deploy is running. Wait, or raise **Concurrent deployments** in the
  server's **Overview**.
- A [build server](/advanced/build-servers) is full. Check that server too.
- The target server is unreachable. Refresh its health.

## No space left on device

Open **Settings -> Servers -> the server -> Cleanup**, then click **Reclaim
disk now**. If little space is freed, check old app images and the build cache.
Set a **Schedule** and review **Images kept per app**.

<Callout type="info" title="No automatic pruning">
Deplo deliberately never runs `system prune`, container prune or volume
prune, because on a Deplo host a stopped app is a live app and a dangling
volume may hold somebody's data.
</Callout>

<Callout type="warn" title="Watch the interaction with rollbacks">
Keep **Images kept per app** at least as high as the app's **Keep**, or rollback
targets can be pruned.
</Callout>

## A rollback fails or is not offered

- **Not offered:** the source is a Docker image or Compose stack, or an
  uploaded archive past **Keep**. Deplo has no image or commit to go back to.
- **Missing image:** it was pruned. Raise **Keep** and **Images kept per app**.
- **Agent too old:** rebuilding an older commit needs a recent server agent.
  Update it from **Settings -> Servers**.

## The deploy succeeded but the app did not change

- Variables and storage changes apply on the next deploy; saving alone does
  not deploy.
- If the rendered Compose stack is unchanged, use **Rebuild container** in
  **Settings -> Advanced**.

## A deploy shows an old error after restart

After a control-plane restart, an in-flight deploy can show `error` even when
the containers are running. A later telemetry update clears that stale state.
