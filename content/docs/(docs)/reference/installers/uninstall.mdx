<Callout type="warn" title="Dry run first">
Without `--yes`, it only lists what it found and prints the commands it would run. **`--purge-data`
is irreversible**: it deletes Deplo's volumes, secrets and data on that host.
</Callout>

<Tabs items={['Uninstall an agent from the host', 'Uninstall Deplo itself']}>
  <Tab value="Uninstall an agent from the host">
    `--agent-only` leaves the control plane in `/opt/deplo` alone. On the control-plane host it
    still removes Traefik, so the panel stops answering until you re-run `install.sh`.

    ```bash
    # See what would happen (dry run, the default)
    curl -fsSL https://deplo.example.com/uninstall.sh | sudo bash -s -- --agent-only

    # Do it
    curl -fsSL https://deplo.example.com/uninstall.sh | sudo bash -s -- --yes --agent-only

    # Do it, and delete the data too
    curl -fsSL https://deplo.example.com/uninstall.sh | sudo bash -s -- --yes --agent-only --purge-data
    ```
  </Tab>
  <Tab value="Uninstall Deplo itself">
    Without `--agent-only`, it also removes the control plane in `/opt/deplo`, its Postgres and
    its Traefik.

    ```bash
    # See what would happen (dry run, the default)
    curl -fsSL https://deplo.example.com/uninstall.sh | sudo bash

    # Do it, keeping every volume and /opt/deplo
    curl -fsSL https://deplo.example.com/uninstall.sh | sudo bash -s -- --yes

    # Do it, and delete the data too
    curl -fsSL https://deplo.example.com/uninstall.sh | sudo bash -s -- --yes --purge-data

    # And the backups stored on this machine
    curl -fsSL https://deplo.example.com/uninstall.sh | sudo bash -s -- --yes --purge-data --purge-backups
    ```
  </Tab>
</Tabs>

<Callout title="When the instance itself is unreachable">
  Use `https://deplo.build/uninstall.sh`. It serves the newest script, so read the dry run
  before adding `--yes` on an older installation.
</Callout>

    "--yes": { type: "flag", description: "Actually do it. Without it, everything is a dry run." },
    "--agent-only": { type: "flag", description: "Leave the control plane in /opt/deplo alone. The dashboard's command for a removed server carries it." },
    "--purge-data": { type: "flag", description: "Also delete Deplo volumes, the images Deplo built, /data/stacks and /data/dev. Without --agent-only, also the panel image and /opt/deplo itself, .env included. Irreversible." },

## What it removes

In order: the control plane (unless `--agent-only`), the `deplo-agent` service and binary,
`deplo-clat` and any NAT64 resolvers it set, Traefik and its socket proxy, every container
labelled `deplo.managed=true`, the `deplo` networks, and `/var/lib/deplo-agent`.

- It never removes Docker Engine, rewrites `/etc/docker/daemon.json`, or touches a container
  Deplo did not create.
- If this Deplo took over another panel that is still on the machine, it starts that panel again.
- It is safe to run on a host that was never a Deplo host, and safe to run twice.

<Callout type="warn">
  **`--purge-data` deletes `/opt/deplo/.env`, and that holds `DEPLO_SECRET`.** Every backup
  artifact this instance wrote is encrypted with a key derived from it. Copy the file first if
  you may ever want to restore one.
</Callout>

The older `/uninstall-agent.sh` URL still works and applies `--agent-only` automatically.
