Deplo keeps one live metrics stream open to each server's agent, for the machine and every
container on it. The last **16 minutes** stay in memory, so charts are full the moment a page
opens. Per-app monitoring has no switch to turn on.

A server with an old agent falls back to polling, with fewer samples.
[`DEPLO_MONITORING_FORCE_POLL=1`](/reference/environment-variables) forces the whole fleet onto it.

| A database's **Monitoring** tab | The same for the engine |

With more than one server, the **Monitoring** page lists one row per server:

- ordered **worst first** by CPU, memory or disk, whichever is fullest; past six rows it scrolls;
- **click a row**, or use the searchable picker, to show that server in the panels below;
- **Agent outdated** marks a server behind the current agent, and an info marker one that samples
  through `docker stats`, which costs more CPU;
- **Manage** opens the server's page, for instance admins only. An app's or database's tab names
  its server with the same button.

## Reading the numbers

Every figure matches what the machine reports in a shell. Sizes are **binary** (KiB, MiB, GiB),
like `df`, `free`, `htop` and `docker`.

### A server

| Reading | What it means |
| --- | --- |
| **CPU** | Share of the whole machine. Time waiting on a disk counts as idle, as in `htop`. |
| **Memory** | Total minus available, the `used` column of `free`. The tile's info marker splits it into `processes` and `cache`. |
| **Disk** | The filesystem holding the agent's data directory, as `df` reports it. |
| **Network** | Real interfaces only. Docker bridges are left out so bytes are not counted twice. |
| **Load average** | The kernel's 1, 5 and 15 minute averages. |

**Memory reads higher than in `htop`, and both are right.** `free` and Deplo count cache that
cannot be reclaimed as used; `htop` counts all cache as free.

CPU, memory and disk are arcs against the whole machine, with what it has in the caption. An arc
turns amber past 80%.

| Reading | What it means |
| --- | --- |
| **CPU** | The arc fills against the [resource limit](/advanced/resource-limits) when set, otherwise the machine (`2.99 of 8 cores`). The **chart** is a percentage of **one** core, like `docker stats`: three busy cores read 300%. |
| **Memory** | Against the machine's RAM, or the resource limit when set. |
| **Network** | Once per network namespace. A sidecar sharing another container's network reads `network shared with <container>`. With `network_mode: host` it reads `host network` and counts on the server's chart instead. |
| **Disk I/O** | Bytes the stack's containers read and write. |
| **Status** | Per container: the healthcheck result when there is one, otherwise the Docker state (`running`, `restarting`, `exited`, `paused`, `dead`). |
| **Restarts** | How many times Docker restarted that container. Amber above zero. |

## Save metrics on server

One instance-wide switch in the **Monitoring options** menu (three dots, top right of the
**Monitoring** page), **on by default**. Needs `manage_monitoring`.

On, charts survive a reload. Off, the stored history is dropped and charts start empty every time.
Live charts work either way. The history lives in the panel's memory, so a panel restart clears
it too.

## Alerts that come from metrics

The same stream raises these [alerts](/guides/observability/notifications-and-alerts):
**Server running hot**, **Server disk almost full**, **Server offline** / **Server back online**,
**Server cannot run apps**, **App keeps restarting** and **App ran out of memory**.

## Good to know

- **The fleet page needs whole-team access.** A member limited to one folder sees **Outside your
  access**.
- **A gap in a chart means no data arrived**, usually a reconnect. It never means zero.
- **An app with [replicas](/advanced/replicas)** shows one total, with every replica in the
  container breakdown. On a cluster the charts add a line per server and mark each failover. See
  [Monitoring on a cluster](/operations/clusters/logs-metrics-and-previews#monitoring).
- **`view_metrics`** (**View monitoring**) is its own capability, grantable per folder.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Dashes, or a fleet row reading **No data** | The stream is not connected. Check that server's health. |
| A container's status is blank | Its agent is too old to report one. Blank never means healthy. |
| A running container shows no healthcheck result | Neither the image nor the app defines one. [Add a health check](/guides/observability/health-checks). |
| An app shows nothing | It is stopped, or its server's agent is not reporting. |
| Charts empty after a panel restart | The history is in memory and starts again. |
| A number does not match a shell | Check the unit: binary sizes, and an app's CPU **chart** is a share of one core. |

More in [Servers and agents](/troubleshooting/servers-and-agents).
