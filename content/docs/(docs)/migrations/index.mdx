Deplo reads a Dokploy or Coolify installation through its API and recreates it here: projects,
apps, databases, domains, variables and volumes, data included. No SSH into the old panel, and
nothing on it is deleted. [Another Deplo](/migrations/move-from-another-deplo) is read the same
way, one team at a time.

## Two routes

| | Take over this server | From another server |
| --- | --- | --- |
| Where Deplo runs | The machine the old panel runs on | A machine of your own |
| How you start it | The installer finds the panel and asks | **Settings -> System -> Migrations** |
| Who can run it | Whoever installs Deplo | An instance admin |
| Where apps land | This machine | A server you pick, per app |
| Ports 80 and 443 | Deplo takes them at the end | Untouched |
| The old panel afterwards | Removed from the machine | Still there, still yours |

Another Deplo always takes the second route. A Deplo agent on each source machine reads the
volumes, and the data passes through the control plane. Another Deplo needs no agent: it hands its
data over itself.

## The wizard

| Step | What it asks for |
| --- | --- |
| **Connect** | The panel's address and a token, one per source team. |
| **Install** | One command to run as root on each source machine. Skipped for another Deplo. |
| **Review** | What comes over and where it lands, then **Start migration**. |
| **People** | Single-use registration links for the panel's members. |
| **Take over** | Takeover only. The confirmation that moves ports 80 and 443. |
| **Done** | The report. |

A takeover starts with one choice: **Bring your data over** or **Start clean**. Start clean jumps
straight to **Take over**.

## What comes across

| Shape | Notes |
| --- | --- |
| An app from a Docker image | Image, tag, environment, ports. A custom command is named in the report. |
| An app from a compose file | Rendered as written, with its named volumes. |
| An app built from a git repository | Repository, branch, build settings. |
| Managed databases | Postgres, MySQL, MariaDB, MongoDB, Redis and ClickHouse, with their data. |
| Named volumes, bind mounts, single-file binds | Copied to the destination and re-pointed. |
| Environment variables | Per app and shared, with their values. |
| Domains and routes | Including a path prefix and a per-domain port. |
| Basic auth | Users and passwords, flagged because they skipped Deplo's password rules. |
| Cron jobs | Schedule and command. |
| Backup destinations and schedules | Tested on arrival. |
| Preview-only variables | As the app's own preview variables. |

Inside a volume, contents, permissions, ownership, empty directories, zero-byte files, long paths,
hard links and symbolic links within the volume are preserved.

## What needs a look

Deplo brings across what it can and lists the rest in the report.

| Shape | What happens |
| --- | --- |
| A stack that reaches the host | `privileged`, `network_mode: host`, `cap_add`, devices: needs the **Bind server folders** permission. Without it the stack stays behind and the report names the keys. |
| An image from a private registry | The reference comes across, the credentials do not. The report names the registry. |
| Device nodes, sockets, named pipes, symlinks leaving their volume | Not copied. Each is listed with its path. |
| State outside the app | A host cron entry, a systemd unit, a file no mount points at. |
| More replicas than one | Deplo runs one container per app. |
| A small destination disk | Deplo warns when the receiving disk has under 5 GiB or 10% free. A copy needs room for both copies. |

Never migrated: Dokploy and Coolify registry passwords and git deploy keys, host files such as
`/etc/localtime`, networks you created by hand, and engines Deplo lacks (`libsql` on Dokploy,
`keydb` and `dragonfly` on Coolify).

## Stopping, data, and going back

- **Every service you tick is stopped on the old panel when its data copy starts**, and stays
  stopped after a finished run.
- **The destination is emptied before it is written.** A second run does not merge two copies.
- **Stop and undo**, in any step, removes everything the run created here with its data and
  starts the stopped services again on the old panel.
- **A run that fails on its own is not rolled back.** A service whose data did not arrive refuses
  to deploy until you copy the data again or press **Deploy anyway**.
- **Nothing is deployed for you.** Open each app, check it, press **Deploy**.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The https certificate **is not one this machine trusts** | Deplo cannot be told to accept it. Use the panel's plain http address, for example `http://203.0.113.10:3000`. |
| **but nothing is running behind it** (a 502, or a Cloudflare 521) | The panel behind the proxy or CDN is down. Start it, or point Deplo at the panel's own address. |
| **This address is Cloudflare's, not the machine's** | The Install row needs the machine's own IP. Enter it there. |
| Stuck on **Waiting for the agent** | The command has not run on that machine, or the machine cannot reach this Deplo. |
| One source machine does not answer | Its services are named in the report and blocked from deploying. The other machines are still copied. |
| A volume arrives empty | The app refuses to deploy until you decide. One volume copy stops after 7 hours, so copy a huge volume over a slow link by hand. |
| **is also mounted by** another app | The copy empties its target first, so nothing was written. Give one app its own directory, then copy the data again. |
| A single-file bind is refused | The destination server's agent is too old. Update it, then copy the data again. |
| **already has a migration running in this team** | One run per team at a time. Wait, or stop it under **Settings -> System -> Migrations**. |
| **Agent still installed** | Deplo removes its agent from source machines when the run ends and could not here. Press **Remove from Deplo**, or run the printed command as root. |
| **The server agent did not install** during a takeover | Re-run `/opt/deplo/install.sh`, or use the command under **Settings -> Servers**. |
| The port move failed | Deplo put the ports back and started the old panel again. The step names what holds the port, next to **Try again**. |
| Stuck on **Moving the ports** | Read `systemctl status deplo-takeover` and `/var/log/deplo-takeover.log`. Re-run the installer and the takeover resumes. Stay on the http address until then. |

Measured on 4 September 2026, each panel on two machines, the remote route landing on a third:
**66 of 67** Dokploy apps and **60 of 62** Coolify apps landed untouched. The misses were one
private git repository (its deploy key never leaves the old panel) and, on Coolify, one app the
token could not stop.
