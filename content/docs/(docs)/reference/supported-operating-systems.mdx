The same installer runs on the dashboard host and every server you add.

## Requirements

| Requirement | Why |
| --- | --- |
| Linux on `x86-64` or `arm64` | The agent binary and the control-plane image are published for these two only. |
| `systemd` | Required for the agent. Without it, the control plane can start but the machine cannot run deployed apps. |
| Root, for the length of one command | It writes a system service and installs packages. |
| `curl` and `sha256sum` | To download the agent and verify its checksum before running it. |
| Docker with Compose v2 | Installed for you when your distribution is one Docker publishes packages for. |

## Tested distributions

These are the safest choices for a first install.

| OS | Status | Notes |
| --- | --- | --- |
| <Os name="ubuntu">Ubuntu 26.04 LTS</Os> | **Tested** | Supported by Canonical until 2031. |
| <Os name="ubuntu">Ubuntu 24.04 LTS</Os> | **Tested** | Supported until 2029. |
| <Os name="debian">Debian 13 (trixie)</Os> | **Tested** | Current stable. |
| <Os name="debian">Debian 12 (bookworm)</Os> | **Tested** | Oldstable, LTS until June 2028. |

## Compatible, not tested

The installer can set Docker up on these, but they are not tested choices.

| OS | Status | Notes |
| --- | --- | --- |
| <Os name="ubuntu">Ubuntu 22.04 LTS</Os> | Compatible | Older Docker, everything else identical. |
| <Os name="fedora">Fedora 43 and 44</Os> | Compatible | A Fedora release goes end of life in about 13 months, so plan the upgrade. |
| <Os name="rocky">Rocky Linux 9 and 10</Os> | Compatible | `firewalld` holds `9443` shut; the installer prints the command to open it. |
| <Os name="centos">CentOS Stream 9 and 10</Os> | Compatible | Same firewall note. |
| <Os name="rhel">RHEL 9 and 10</Os> | Compatible | Same firewall note. |
| <Os name="raspberrypi">Raspberry Pi OS 64-bit</Os> | Compatible | The 32-bit image will not work, see below. |

<Callout type="info" title="Version 8 of the RHEL family">
  Rocky, AlmaLinux, CentOS and RHEL 8 still install, but they boot on cgroup v1 and Deplo reads
  container metrics from cgroup v2. Everything deploys, the Monitoring charts stay empty.
</Callout>

## Bring your own Docker

These work when Docker and Compose v2 are already installed. The installer
does not install Docker for them.

| OS | Status | Notes |
| --- | --- | --- |
| <Os name="almalinux">AlmaLinux 9 and 10</Os> | Bring your own Docker | Takes the CentOS packages, built against the same release. |
| <Os name="opensuse">openSUSE Leap 15</Os> | Bring your own Docker | Docker and Compose v2 are in its own repositories. |
| <Os name="arch">Arch Linux</Os> | Bring your own Docker | Docker and Compose v2 are in `extra`. |
| <Os name="linux">Any other distribution with systemd</Os> | Bring your own Docker | `docker compose version` has to answer 2.x or newer. |

Install Docker first, then run the Deplo command normally. It detects Docker
and skips that step.

<Tabs items={['AlmaLinux', 'openSUSE Leap', 'Arch Linux']}>
<Tab value="AlmaLinux">

```bash
dnf -y install dnf-plugins-core
dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
dnf -y install docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl enable --now docker
```

</Tab>
<Tab value="openSUSE Leap">

```bash
zypper --non-interactive install docker docker-compose
systemctl enable --now docker
```

</Tab>
<Tab value="Arch Linux">

```bash
pacman -Sy --noconfirm docker docker-compose
systemctl enable --now docker
```

</Tab>
</Tabs>

The one thing to check afterwards is `docker compose version`. Deplo needs the Compose plugin,
version 2 or newer, not the old standalone `docker-compose` binary.

## Not supported

| OS | Status | Why |
| --- | --- | --- |
| <Os name="alpine">Alpine Linux</Os> | **Not supported** | No `systemd`. The agent is a systemd unit, so the preflight refuses before anything is installed. |
| <Os name="suse">SUSE Linux Enterprise</Os> | **Not supported** | Docker publishes `docker-ce` for SLES on IBM Z only. There is no `x86-64` or `arm64` package to install. |
| <Os name="linux">32-bit Linux (`armhf`, `i386`)</Os> | **Not supported** | The agent binary is published for `amd64` and `arm64` only. This is the 32-bit Raspberry Pi OS image. |
| Windows, macOS | **Not supported** | Deplo runs Linux containers on a Linux host. |

<Callout type="warn" title="arm64 is published, not tested">
  Deplo publishes an `arm64` agent and an `arm64` image, and the installer accepts the
  architecture. Nothing in the platform is `x86-64`-specific, but we have not run a fleet on ARM,
  so treat it as compatible rather than proven.
</Callout>

## Check before installing

The preflight changes nothing and prints blocking problems and warnings:

<Tabs items={['The dashboard host', 'A server you are adding']}>
<Tab value="The dashboard host">

```bash
curl -fsSL https://deplo.build/install.sh | bash -s -- --check
```

</Tab>
<Tab value="A server you are adding">

Take the command the dashboard gives you under **Servers - Add server** and append `--check`:

```bash
curl -fsSL https://<deplo>/install-agent.sh | sudo bash -s -- <TOKEN> <URL> --check
```

</Tab>
</Tabs>
