An app is one deployable unit: a repository, an uploaded archive, a Docker image or a compose stack. Its settings have their own page, [App settings](/api-reference/app-settings); shipping it is on [Deployments](/api-reference/deployments).

<Callout type="info" title="search(q) is not scoped to the active team">
  It answers with hits from every team the caller can reach, each carrying the team it lives in, so a client that has a name but not a team can find it and then work there (with `X-Deplo-Team` for a token, or the `team` argument of an MCP tool). A team the caller cannot enter right now contributes nothing. At most 50 hits per kind.
</Callout>

## Reading

### `apps`

Any signed-in principal. Returns [`[App!]`](/api-reference/types/objects#app).

All apps in the active team, newest first.

| Argument | Type | Description |
| --- | --- | --- |
| `q` | `String` | Keep only the apps whose name, slug or id contains this, ignoring case and separators. Use `search` to look across teams. |

```graphql
query {
  apps(q: "shop") {
    id
    slug
    name
    status
    latestDeployment { status createdAt }
  }
}
```

### `search`

Any signed-in principal. Returns [`SearchResults`](/api-reference/types/objects#searchresults).

Find anything by name, slug or id across EVERY team the caller can reach - the one read in Deplo that is not scoped to the active team. Each hit says which team it is in. Separators and case are ignored, so "better auth" finds `better-auth-docs`. Hits from the active team come first, then the closest match. Teams the caller cannot enter right now (an unmet two-factor policy, a narrowed token) contribute nothing rather than failing the search.

| Argument | Type | Description |
| --- | --- | --- |
| `kinds` | [`[SearchKind!]`](/api-reference/types/enums#searchkind) | Which kinds to look through. Omitted means all ten - and each is a separate read PER TEAM, so name the ones you need.  |
| `q` | `String!` | Part of a name, slug or id. Blank finds nothing. |

```graphql
query {
  search(q: "shop", kinds: [app, database]) {
    apps { id slug name team { slug } }
    databases { id name team { slug } }
  }
}
```

## Creating

`createApp` takes the whole first configuration in one input. The new-app wizard runs `detectRepoFramework` while you pick a repository and `composeNameClashes` before it submits a stack.

### `createApp`

Needs `create_apps`. Returns [`App`](/api-reference/types/objects#app).

Create an app from a repository, an uploaded archive, a Docker image or a compose stack, with its first build settings, variables, domains and mounts. Deploys immediately unless the source needs an upload first.

| Argument | Type | Description |
| --- | --- | --- |
| `input` | [`CreateAppInput!`](/api-reference/types/inputs#createappinput) |  |
| `input.autoDeploy` | `Boolean` |  |
| `input.autoDomain` | `String` |  |
| `input.autoDomainPath` | `String` |  |
| `input.build` | [`BuildConfigInput`](/api-reference/types/inputs#buildconfiginput) |  |
| `input.buildServerId` | `String` | Where the app COMPILES, when that is not where it runs. Omitted is Automatic - a build-only server if the fleet has one. |
| `input.compose` | `String` |  |
| `input.composePort` | `Int` |  |
| `input.composeService` | `String` |  |
| `input.composeUpArgs` | `String` | Extra flags appended to `docker compose up` for a compose stack. Validated against the same allow-list the app's settings use. |
| `input.dockerImage` | `String` |  |
| `input.env` | [`[AppEnvInput!]`](/api-reference/types/inputs#appenvinput) |  |
| `input.environmentId` | `String` |  |
| `input.extraDomains` | [`[ExtraDomainInput!]`](/api-reference/types/inputs#extradomaininput) |  |
| `input.folderId` | `String` |  |
| `input.logo` | `String` |  |
| `input.logoFromTemplate` | `Boolean` | The logo above is a template's own. Deplo reads it once for the plate that keeps a monochrome mark visible on both themes. |
| `input.mounts` | [`[MountInput!]`](/api-reference/types/inputs#mountinput) |  |
| `input.name` | `String!` |  |
| `input.projectId` | `String` |  |
| `input.renameClashes` | `Boolean` | Rename a service whose name a neighbour on the destination network already answers to (`db` becomes `db-2`), carrying its references, instead of refusing the stack. See `composeNameClashes`. |
| `input.repo` | [`GitRepoInput`](/api-reference/types/inputs#gitrepoinput) |  |
| `input.serverId` | `String` |  |
| `input.sharedVarIds` | `[String!]` | Shared variables to link to the new app, so its FIRST deploy already carries them (ADR-0012: linking is the injection, and it is opt-in). |
| `input.source` | [`DeploySource!`](/api-reference/types/enums#deploysource) | One of `COMPOSE`, `DOCKER_IMAGE`, `GIT`, `GITHUB`, `UPLOAD`. |

```graphql
mutation {
  createApp(
    input: {
      name: "shop"
      source: GITHUB
      repo: { provider: "github", repo: "acme/shop", branch: "main", url: "https://github.com/acme/shop", installationId: "ghi_9f1c2ab7d3e4f5a6" }
      build: { buildMethod: "nixpacks", port: 3000 }
      env: [{ key: "NODE_ENV", value: "production" }]
      autoDeploy: true
    }
  ) {
    id
    slug
    name
    status
    productionUrl
  }
}
```

### `detectRepoFramework`

Needs `create_apps`. Returns [`RecognizedFramework`](/api-reference/types/objects#recognizedframework).

Read a GitHub repository before an app exists for it - the framework and the build command the new-app wizard prefills while you pick a repo. Null when there is nothing to read at all: a build method other than Nixpacks / Railpack (the only ones this applies to), a repository Deplo can't read, or one with neither a framework nor a script. Reads only; the app's first deploy re-derives and stores the framework.

| Argument | Type | Description |
| --- | --- | --- |
| `branch` | `String` | Branch to read; empty => the repository's default branch. |
| `buildMethod` | `String!` | The build method the app will use, e.g. "nixpacks". |
| `installationId` | `String` | GitHub App installation to read a private repo through. Ignored unless it belongs to the active team. |
| `repo` | `String!` | The repository as "owner/name". |
| `rootDirectory` | `String` | Build sub-directory, for a monorepo. |
| `url` | `String` | Its clone URL, when the caller has one (else derived). |

```graphql
query {
  detectRepoFramework(repo: "acme/shop", buildMethod: "nixpacks", installationId: "ghi_9f1c2ab7d3e4f5a6") {
    id
    name
    buildCommand
    startCommand
    defaultPort
  }
}
```

### `bulkAppAction`

Needs `control_apps`. Returns [`BulkAppActionResult`](/api-reference/types/objects#bulkappactionresult).

Start, stop or restart EVERY app in one folder (its whole subtree) or one project (every environment). Gated again per app, so it only touches the ones the caller may control; one failure never stops the rest. Give exactly one of folderId / projectId.

| Argument | Type | Description |
| --- | --- | --- |
| `action` | [`BulkAppAction!`](/api-reference/types/enums#bulkappaction) | One of `restart`, `start`, `stop`. |
| `folderId` | `ID` |  |
| `projectId` | `ID` |  |


### `transferAppToTeam`

Needs `move_apps`. Returns `Boolean`.

Hand this app over to another team the viewer belongs to. The app keeps running: it leaves its folder/project, loses its shared-variable links and backup schedules, and keeps its GitHub connection only if the destination team has its own installation on that account. Returns true.

| Argument | Type | Description |
| --- | --- | --- |
| `appId` | `String!` |  |
| `teamId` | `String!` |  |

```graphql
mutation {
  transferAppToTeam(
    appId: "prj_9f1c2ab7d3e4f5a6"
    teamId: "team_9f1c2ab7d3e4f5a6"
  )
}
```

### `deleteApp`
