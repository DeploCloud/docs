Run an image that is already built, from Docker Hub, GitHub Container Registry or any registry
you can reach, like `nginx:1.27-alpine` or `ghcr.io/acme/api:v2.3.1`. The agent pulls it and
starts it.

Use it for software you did not write and for images your own CI builds. Nothing is built, so
there is no build log, no build cache and **no rollback**: the tag is your version control.

## Deploy one

1. **Add New**, then **Application**, then the **Docker Image** tile.
2. Type the reference. Docker Hub names autocomplete, and a `:` lists the tags. **App name** is
   filled in from the image.
3. Click **Deploy**. The server and the port are under **Advanced**, already filled in.

A green check next to the reference means the image exists. A lock means it is private: the check
runs without your registry credentials, but the deploy pulls with them.

## The port

**Deplo reads the port from the image's `EXPOSE`**: `nginx` and `traefik/whoami` give 80. An
image that declares several ports or none, or that is private, gets **3000**.

- **Before the first deploy:** **Advanced**, **Container port**.
- **After:** each hostname's **Application port** in the app's **Domains** tab. It applies
  without a redeploy, and lets one image serve two hostnames on two ports.

An official database image (`postgres`, `mysql`, `mariadb`, `mongo`, `redis`,
`clickhouse/clickhouse-server`) gets no address. For a database, use
[Databases](/guides/data/databases).

## Private registries

Add credentials once in **Settings -> Registries** and every app of the team pulls with them. See
[Container registries](/operations/servers/container-registries).

## Settings that matter for an image app

| Setting | Where | Note |
| --- | --- | --- |
| Image reference | **Settings -> Deployments**, **Source** card | Change the tag, **Save source**, then **Redeploy** |
| Environment variables | **Environment** | The usual way to configure this kind of software |
| Volumes | **Settings -> Storage** | Type the full path, like `/app/uploads`: it is not guessed |
| Resource limits | **Settings -> Resources** | Useful for software you did not write |

## Good to know

- **Pin a tag or a digest**, not `latest`. `latest` is pulled again only on a redeploy, and
  [Security updates](/guides/observability/security-updates#update-an-image) offers **Update**
  when a newer build fixes a flaw.
- **Names under `deplo/` are refused.** That is where Deplo keeps the images it builds for apps.
- **Multi-container software needs Compose.** If the vendor ships a `docker-compose.yml`, use
  [Compose apps](/advanced/compose-apps) or look in [Templates](/guides/deploy/from-template).

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `pull access denied` | The image is private and no registry credential matches its host. Add one in **Settings -> Registries**. |
| The container starts and exits immediately | It usually needs a variable or a volume. Read the [Logs](/guides/observability/logs). |
| The URL answers 502 | Wrong port: Deplo could not read one from the image and used 3000. Set **Application port** on the domain. |

More in [Deploys and builds](/troubleshooting/deploys-and-builds).
