The **Deploy on Deplo** button puts your project one click away from anyone who runs Deplo. It
opens **their** Deplo, on **their** server, with your stack already filled in.

<DeployButton compose="https://github.com/DeploCloud/templates/blob/main/src/templates/actual-budget/default/docker-compose.yml" />

Try it: the button above deploys [Actual Budget](https://actualbudget.org) on your Deplo.

## Quick start

Copy a snippet and put the link to your `docker-compose.yml` after `compose=`.

<Tabs items={["Markdown", "HTML", "URL"]}>
<Tab value="Markdown">

```md
[![Deploy on Deplo](https://deplo.build/button.svg)](https://deplo.build/deploy?compose=https://github.com/acme/app/blob/v1.2.0/docker-compose.yml)
```

</Tab>

`compose` is the only parameter: an `https` link to the file. A GitHub or GitLab page link works,
Deplo turns it into the raw file. No account, nothing to register.

## What happens on click

1. **deplo.build finds their Deplo.** The first time, it asks for its address, like
   `deplo.acme.com`. After that, a 3-second countdown, with **Deploy now**, **Change instance**
   and **Cancel**.
2. **Their Deplo reads your files**: your `docker-compose.yml`, plus a `template.toml` and a logo
   if they sit next to it. They sign in if needed, and land in the new-app wizard of the last
   team they used.
3. **They review and deploy.** The wizard is the one a [template](/guides/deploy/from-template)
   opens, with the warning **Not from the Deplo catalog. Review it before you deploy.** and **Edit
   compose** to read the stack. Nothing is created until they click **Deploy**.

## Configure the deploy

Put these in the same folder as the compose file:

```
acme-app/
├── docker-compose.yml   the stack (required)
├── template.toml        variables, secrets, which service gets the domain
└── logo.svg             the icon (or logo.png)
```

`template.toml` is the format of the [template catalogue](https://github.com/DeploCloud/templates):

```toml title="template.toml"
[variables]
db_password = "${password:32}"

[config]
mounts = []

[[config.domains]]
serviceName = "web"
port = 3000
host = "${domain}"

[config.env]
DATABASE_PASSWORD = "${db_password}"
```

| Helper | Becomes |
| --- | --- |
| `${password:32}` | A random secret of that length. `secret`, `jwt` and `base64` work too. |
| `${hash:64}` | A random hex string of that length. |
| `${uuid}` | A random UUID. |
| `${domain}` | The address Deplo gives the app. |

Without a `template.toml`, Deplo picks the web service and its port itself, and the reader fills
in any variables.

## Pin a version

The file is read when someone clicks, not when you write the link. Link a tag, like
`/blob/v1.2.0/docker-compose.yml`, and every reader gets `v1.2.0`. Link `/blob/main/` and they
get whatever is on `main` that day.

## Limits

- **A public https link.** Private repositories are not supported.
- **Images only.** A service with `build:` and no `image:` needs the repository: deploy it
  [from Git](/guides/deploy/from-git) instead.
- **Only the three files above are read.** An `env_file:` or a config file beside the compose is
  not: ship it as a `[[config.mounts]]` entry in `template.toml`.
- **Sizes:** compose 256 KiB, `template.toml` 64 KiB, logo 2 MiB. All three within 10 seconds.
- **Needs a Deplo newer than 0.3.0.** An older one opens an empty wizard.

<Callout type="info" title="The reader's address stays in their browser">
  deplo.build keeps the address of their Deplo in their browser only, and never receives it. It
  counts clicks per repository, and not even that once they turn statistics off on the
  [privacy page](https://deplo.build/privacy). **Forget** on
  [deplo.build/deploy](https://deplo.build/deploy) removes the address.
</Callout>

## Troubleshooting

Deplo shows these under **That compose file isn't available**. The first one comes from
deplo.build itself.

| Message | What to do |
| --- | --- |
| This button's link is broken: it has to point at an https compose file. | The link after `compose=` is missing or not `https://`. |
| `raw.githubusercontent.com` has no file at this address. | Check the link, the tag and that the repository is public. |
| This file isn't a Compose file: it has no services. | The link points at a web page, not at the file. Link the file itself. |
| The "web" service builds from source, which needs the repository. | Publish an image and use `image:`, or deploy from Git. |
| The compose file is too large (256 KiB max). | Trim it, or split it into several apps. |
| The compose URL must not point at a private or internal address | The file has to be on the public internet. |
| `raw.githubusercontent.com` took too long to answer. | Try again: the file host is slow or down. |
