Deploy an archive of your project instead of connecting a repository: for code that is not in
Git, a one-off, or code Deplo cannot reach. Deplo builds it like a clone, with the same
[build methods](/guides/releases/build-settings#build-methods).

## Deploy one

1. **Add New**, then **Application**, then the **Upload** tile. Or drop the archive anywhere on
   the Overview: the wizard opens with the file loaded.
2. Drop the archive on the card, or click to browse: `.tar.gz`, `.tgz`, `.tar` or `.zip`, up to
   512 MiB. **App name** is filled in from the filename.
3. Click **Deploy**. The server, the build settings and the **Root directory** are under
   **Advanced**.

`package.json` (or the equivalent) goes at the top level of the archive. A single top-level
folder is fine: Deplo steps into it.

To ship a new version: **Settings -> Deployments**, drop a new archive on the **Source** card, then
**Save & Deploy**.

## Good to know

- **No automatic deploys.** There is no repository to watch. A
  [deploy hook](/guides/releases/automatic-deployments#the-deploy-hook) can start a build from CI,
  but it rebuilds the archive already stored.
- **Rollbacks go back to kept builds only.** There is no commit to rebuild. See
  [Rollbacks](/guides/releases/rollbacks).
- **A new archive replaces the previous one.** There is no upload history.
- **Leave out `node_modules` and build output.** They make the upload huge, and the build
  reinstalls dependencies anyway.
- **Symbolic links are refused**, and so is an archive that unpacks past 4 GiB or 500,000 files.

## Troubleshooting

| Message | What to check |
| --- | --- |
| Unsupported archive - use .tar.gz, .tgz, .tar or .zip | Repackage in one of those formats. |
| Archive too large (max 512 MiB) | Leave out `node_modules` and build output. |
| Empty archive | The file has no content. |
| A deploy is already running - wait for it to finish | Upload again when the current deploy ends. |
| The deploy fails with `archive contains a symlink` | Replace the link with the real file. |

More in [Deploys and builds](/troubleshooting/deploys-and-builds).
