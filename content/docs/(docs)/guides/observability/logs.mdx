What your containers print, live, plus the output of every build. No `docker logs`, no SSH.

- **Runtime logs** stream from the agent while the page is open.
- **Build logs** are saved, so they survive a reload and a panel restart. Capped at 20,000
  lines of 4,000 characters each.

## The pane

| Control | What it does |
| --- | --- |
| Container | Which container of the stack you watch. Shown only when there is more than one |
| Search logs | Keep lines containing a text |
| Level | `info`, `warn`, `error`, `debug`, `success`, or **All levels**. Deplo detects the level of each line, so it works with any software. Build logs add `command` |
| Time range | Last 30 minutes, hour, day or 7 days (the default). **Show timestamps** and **Format** live here too |
| Pause | Stops **auto-scroll**, not the stream |
| Clear, Copy, Download | Empty the pane, copy it, or save it as `<container>.log` |
| Reconnect | Reopen a stream that `ended` or `failed` |
| Display | Text size and line spacing |

The stream's state sits next to the toolbar: `connecting`, `streaming`, `reattaching`,
`ended` or `failed`. A chip explains what the stream cannot: **Stopped**, **No container**,
**12 restarts**, **Unhealthy**, **Not running** or **3/5 up**. Click it for details.

## Retention

How far back the time range reaches is an instance setting: **Settings -> Deplo -> Advanced ->
Log search range**. Default **7** days, from 1 to 90, instance admins only. Above 7, the range
menu gains a **Last N days** entry.

It does not make the server keep more. Each container keeps its latest **100 MB** of output
(five 20 MB files, compressed), and the oldest lines make room. A Compose service with its own
`logging:` keeps it. For long retention, ship logs to a tool built for it.

## Restart loop protection

**After 10 restarts in 30 minutes**, Deplo stops a crashing container so it cannot burn CPU and
fill the disk. Then:

- the Logs page says **Stopped**, with a **Start** button for when you have fixed it;
- the app or database turns red, **App keeps restarting** goes out, and **Activity** records it;
- in a Compose stack, only the looping service stops. The others keep serving.

A deploy resets the count, and restarts spread wider than 30 minutes never add up.

To let a container keep crashing, turn **Restart loop protection** off in the app's or
database's **Settings -> Advanced**. It applies at once, with no redeploy.

## Good to know

- **This is a live tail with filters, not a log search engine.**
- **A crash loop still streams.** You see each attempt's output.
- **`view_logs` is its own capability**, grantable per folder. Without it, an app shows a closed
  state, not an empty pane.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Empty pane, app running | The app writes to a file. Only stdout and stderr are captured. |
| **No logs yet**, with **View build logs** | No container: the app never deployed, or the stack is gone. Read the build. |
| **Not running** | The container exists but is stopped. Start it, or read the last build. |
| **Stopped**, after repeated crashes | Restart loop protection. Fix what the logs show, then **Start**. |
| The state reads `ended` | The container was recreated. Press **Reconnect**. |
