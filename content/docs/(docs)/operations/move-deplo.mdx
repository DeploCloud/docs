**Move Deplo** copies your whole Deplo onto another machine: a bigger box, a different provider, or
your own machine instead of a hosted one.

Everything comes across exactly as it was:

- every team, account, role, app, database, variable, domain and backup
- each app's data, and the exact version it runs, with no rebuild
- folders an app mounts from its server, except system and read-only ones, which the progress page
  lists
- API tokens and deploy hooks, which keep working

**The old Deplo keeps running, untouched.** It keeps its servers and its apps keep serving. You
switch over when you are ready, one domain at a time, and retire the old one whenever you choose.

<Callout title="Bringing only some teams?">
Use [Move from another Deplo](/migrations/move-from-another-deplo) instead. It brings teams into a
Deplo that already runs other teams.
</Callout>

## Before you start

| Check | Why |
| --- | --- |
| The new Deplo is a **fresh install** | The copy replaces everything on it. One account, no apps or databases. Servers you added are fine. |
| Both run the **same version** | Update the older one under **Settings -> Deplo -> Updates**. |
| The old Deplo has an **https** address | The copy carries every secret, so it never runs over plain http. |
| The new Deplo has an address | Set it under **Settings -> Deplo**. |
| The new Deplo has room | Every app and database runs there too. Add servers to it first if one machine is not enough. |

## Move it

<Steps>
<Step>
### Install Deplo on the new machine
```bash
curl -fsSL https://deplo.build/install.sh | bash
```
Sign in, then leave it empty. Add servers now if you want the apps spread over several.
</Step>

<Step>
### Create a move code on the old Deplo
**Settings -> Migrations**, then **Moving this Deplo to another machine? Create a move code**
under the two choices. Press **Create move code**.

The code starts with `dmove_`, is shown once, and works for one hour until the new Deplo uses it.
</Step>

<Step>
### Connect from the new Deplo
**Settings -> Migrations**, then **Another Deplo -> Everything**. Enter the old Deplo's address, for
example `https://deplo.example.com`, and the `dmove_...` code.
</Step>

<Step>
### Choose where everything lands
You see what comes across, and every server of the old Deplo with a server here to land on. Each
one defaults to this machine; pick another server to spread the load.

Two databases with the same name on different old servers cannot land on the same server here: the
review says so, and you put one of them elsewhere.
</Step>

<Step>
### Start the move
Press **Start move** and confirm. You land on the progress page:

1. **Copy everything**: the old Deplo's data is copied here.
2. **Deploy and copy data**: each app and database starts here, and its data is copied in.
3. **Finish**.
</Step>

<Step>
### Sign in again
The copy signs everyone out of the new Deplo. Press **Sign in** and use the account you had on the
old one. Everyone else does the same.
</Step>
</Steps>

<Callout type="warn" title="Keep the progress page to yourself">
Its address works without signing in, because the copy signs everyone out. Whoever has it can
follow and retry the move. Once the copy is in, cancelling or finishing early needs an instance admin.
</Callout>

## What the old Deplo notices

Almost nothing. It never pauses as a whole, and stays fully usable the whole time.

An app or database **with data** stops on the old Deplo for as long as its own data copies, then
starts again. One without data never stops. While it is paused, the old Deplo will not deploy or
restart it. If the new Deplo stops answering mid-copy, the old one starts what it paused on its own
after a couple of minutes.

Changes made on the old Deplo after the copy started do not come across. Make them on the new one
once it is done.

## Switch over

The new Deplo runs a full copy, but your domains still point at the old servers, so the old Deplo
keeps serving your traffic until you move them.

<Steps>
<Step>
### Point each domain at its new server
For example, change the `A` record of `shop.example.com` to the IP of the server it landed on.
Deplo issues the certificate as soon as the domain answers there.
</Step>

<Step>
### Turn on schedules
The new Deplo starts with **crons and scheduled backups paused**, so nothing runs twice while both
Deplos are up. A banner offers **Turn on**: press it once the new Deplo is the one you use.
</Step>

<Step>
### Keep the panel's address, if you want
Point the old panel domain at the new machine and set it under **Settings -> Deplo**. Passkeys and
webhook addresses are tied to that address: with a new one, people sign in with their password and
set passkeys up again, and webhooks have to be changed.
</Step>
</Steps>

## Two Deplos, from now on

After the move the two live independently. Anything you change on one stays there.

- **API tokens, deploy hooks and members** exist on both. Revoking a token on one leaves it working on
  the other, until you retire the old Deplo.
- **Backups made before the move** show on both. The new Deplo never deletes them, because the old
  one still lists them. Backups kept on a server's disk stay on the old server.
- **Pushes** keep deploying on the old Deplo, because your git provider still calls it. Deploy the new
  one by hand, or point the webhooks at it when you switch.

When you no longer need the old Deplo, [uninstall it](/operations/remove-a-server-or-uninstall).

## If something goes wrong

| What you see | What to do |
| --- | --- |
| Some apps failed with a reason | Fix what it names, then press **Try again**. Only the failed and waiting ones run again. |
| One app keeps failing | **Skip** it. The move finishes without it; add it again by hand. |
| You want to stop | **Cancel move**. The old Deplo starts anything it paused, and the new one goes back to setup. |
| The old Deplo is gone mid-move | **Finish without the old Deplo**. Apps whose data never came across are left out. |

## Common messages

| Message | Fix |
| --- | --- |
| **Needs an empty Deplo** | Move into a fresh install, or bring only some teams instead. |
| **The old Deplo runs an older version** | Update it, then connect again. |
| **This move code expired** | Create a new one on the old Deplo. |
| **This move code is already in use by another Deplo** | A code works for one new Deplo only. Create a new one. |
