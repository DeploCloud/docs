title: Deploys and builds
description: Fix failed builds, unreachable apps, missing deploys, and full servers.
---

<Accordions>
<Accordion title="The build fails">

**Read the build log first.** Use the last error line to choose the fix.

| In the log | Cause | Fix |
| --- | --- | --- |
| `command not found` | Detection chose the wrong command, or a dependency is missing | Set **Build command** in **Settings -> Deployments**, or add the dependency |
| `Cannot find module` | The build ran in the wrong directory | Set **Root Directory** |
| `pull access denied` | A private image with no matching credential | Add the registry in **Settings -> Registries** |
| `Authentication failed` while cloning | The Git credential expired or was revoked | **Settings -> Git**, then **Test connection** |
| `no space left on device` | The server's disk is full | See "No space left on device" below |
| The log ends with nothing | The builder was killed, usually for lack of memory | Raise the memory limit, or use a bigger build server |

Detection runs on every deploy. If it changed after a repository change, set
the commands explicitly; explicit settings win.

</Accordion>
<Accordion title="The build passes but the app is unreachable">

Check these in order:

1. **Container port:** it must match the port your process listens on.
2. **Bind address:** listen on `0.0.0.0`, not `127.0.0.1`.
3. **Container status:** read the app's **Logs** if it exited.
4. **Domain state:** only a routable domain can reach the app. See
   [Domains and TLS](/troubleshooting/domains-and-tls).

Use the generated `https://deplo-<hex>.nip.io` address to separate an app
problem from a DNS or certificate problem.

</Accordion>
<Accordion title="The app restarts, is unhealthy, or has no container">

Open the app's **Logs** tab and look at the runtime notice:

- **Restarting:** the process starts and exits repeatedly. Check its command,
  required variables, and the last log lines.
- **Unhealthy:** the container is running but its healthcheck fails. Check the
  path, port, command, and whether `curl` or `wget` exists in the image.
- **Degraded:** a Compose service is missing or stopped. Check the service
  named in the notice and its logs.
- **Not running:** the app is deployed but no container is running. The logs
  usually show why it exited.

After changing variables, the healthcheck, or storage, **Redeploy**. Use
**Rebuild container** only when the rendered stack must be recreated.

</Accordion>
<Accordion title="A push does not start a deploy">

| Check | Where |
| --- | --- |
| Is **Deploy on push** on? | **Settings -> Deployments** |
| Is the webhook healthy? | Same page. A red state means the provider cannot reach this instance |
| Is it the branch the app tracks? | **Deploy source** |
| Do **Watch paths** exclude what you pushed? | Same page. Empty means deploy on anything |
| Is it a bare Git URL? | Then there is no webhook at all. Use the [deploy hook](/guides/releases/automatic-deployments) |

If the panel address changed, update the webhook or use a new deploy hook.

</Accordion>
<Accordion title="A deploy is stuck in the queue">

Deploys to one server run one at a time by default. Check the build log and
the target server:

- Another deploy is running. Wait, or raise **Concurrent deployments** in the
  server's **Overview**.
- A [build server](/advanced/build-servers) is full. Check that server too.
- The target server is unreachable. Refresh its health.

</Accordion>
<Accordion title="No space left on device">

Open **Settings -> Servers -> the server -> Cleanup**, then click **Reclaim
disk now**. If little space is freed, check old app images and the build cache.
Set a **Schedule** and review **Images kept per app**.

<Callout type="info" title="No automatic pruning">
Deplo deliberately never runs `system prune`, container prune or volume
prune, because on a Deplo host a stopped app is a live app and a dangling
volume may hold somebody's data.
</Callout>

<Callout type="warn" title="Watch the interaction with rollbacks">
Keep **Images kept per app** at least as high as the app's **Keep**, or rollback
targets can be pruned.
</Callout>

</Accordion>
<Accordion title="A rollback fails or is not offered">

- **Not offered:** the source is a Docker image or Compose stack, or **Keep**
  is `0`. Deplo did not build an image to roll back to.
- **Missing image:** it was pruned. Raise **Keep** and **Images kept per app**.

</Accordion>
<Accordion title="The deploy succeeded but the app did not change">

- Variables and storage changes apply on the next deploy; saving alone does
  not deploy.
- If the rendered Compose stack is unchanged, use **Rebuild container** in
  **Settings -> Advanced**.

</Accordion>
<Accordion title="A deploy shows an old error after restart">

After a control-plane restart, an in-flight deploy can show `error` even when
the containers are running. A later telemetry update clears that stale state.

</Accordion>
</Accordions>
