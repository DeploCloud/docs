Every app gets a generated `nip.io` address from its first deploy. To serve it on a hostname you
own, point that hostname at the server and add it to the app. A new domain is created without a
certificate, on plain HTTP; you opt into HTTPS by picking a provider, and nothing is registered
with Let's Encrypt until you do.

## Point the domain at the server

<Steps>
<Step>

### Find the server's public IP

It is on the server card in **Settings -> Servers**, and it is also the hexadecimal part of the
app's generated `nip.io` URL.

</Step>
<Step>

### Create an A record

At your DNS provider, create an **A record** for the hostname, pointing at that IP. For
`app.example.com` on `203.0.113.10`:

```
Type   Name   Value          TTL
A      app    203.0.113.10   auto
```

</Step>
</Steps>

## Add it in Deplo

<Steps>
<Step>

### Open the app's Domains tab

Click **Add Domain** and type the hostname, for example `app.example.com`.

<Image
  src={`${basePath}/screenshots/add-a-domain/01-domains-tab.png`}
  alt="The Domains tab of an app"
  width={1728}
  height={1080}
  className="w-full rounded-lg"
/>

</Step>
<Step>

### Turn on HTTPS

Open **Advanced settings**, then the **HTTPS** group, and set **Certificate** to **Let's
Encrypt**. Behind Cloudflare's orange cloud, Deplo detects the proxy and selects **Cloudflare**
for you.

<Image
  src={`${basePath}/screenshots/add-a-domain/02-add-domain-dialog.png`}
  alt="The Add a domain dialog with the DNS check"
  width={1728}
  height={1080}
  className="w-full rounded-lg"
/>

</Step>
<Step>

### Confirm, and wait for DNS

Click **Add domain**. The row reads **Waiting for DNS** until the record resolves to this server,
then becomes routable on its own. Traefik requests the certificate the first time somebody loads
the site over HTTPS, which takes a few seconds and renews itself from then on.

</Step>
<Step>

### Set it as primary

Open the row's menu and choose **Set as primary**. The primary hostname is the one shown in the
app header and used as the production URL.

</Step>
</Steps>

Let's Encrypt validates over HTTP, so port 80 must be reachable from the internet even for a site
you only intend to serve on 443.

## No domain yet?

The **Add Domain** dialog has a **Generate** button that mints another free `nip.io` hostname on
the spot: a second entry point, a staging name, or just a shorter URL than the generated one. It
cannot hold a certificate, so it stays on plain HTTP.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Stuck on **Waiting for DNS** | The record has not propagated, or it points at a different machine. Check with `dig +short app.example.com`. |
| The browser shows a certificate warning | The certificate has not issued. Almost always port 80 is closed, or the domain resolves elsewhere. |
| 404 from the proxy | The domain resolves and the certificate is fine, but no router matches. Usually the app is stopped, or the domain sits on an app running on a different server. |

More in [Domains and TLS](/troubleshooting/domains-and-tls).
