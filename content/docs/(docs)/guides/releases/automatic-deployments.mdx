A deploy can start without anybody clicking. How depends on the source:

| Source | What starts a deploy |
| --- | --- |
| A **GitHub App** | A push, through the App's one webhook |
| A **GitLab, Bitbucket or Gitea** connection | A push, through a webhook Deplo adds to each repository |
| A plain Git URL, an upload, a Docker image, a pasted Compose app | A `POST` to the [deploy hook](#the-deploy-hook), from CI, a cron job or a script |

## Deploy on push

<Steps>
<Step>

### Turn it on

**Settings -> Deployments**, the **Releases** card: turn on **Deploy on push**. The switch saves
itself.

</Step>
<Step>

### Set the trigger

In the **Trigger** drawer, **Deploy trigger** is either:

- **On push to branch** (default): the branch on the **Source** card.
- **On new tag**: every new tag, whatever the branch.

</Step>
<Step>

### Optional: submodules and watch paths

- **Include submodules** clones submodules too, nested ones included, only from the repository's
  own git server. One hosted elsewhere stops the build and is named.
- **Watch paths (optional)**: one glob per line. A push deploys only if it changed a matching
  file, so each app of a monorepo rebuilds only for its own code:

```
apps/web/**
packages/ui/**
```

Click **Save** on the card.

</Step>
</Steps>

For GitLab, Bitbucket or Gitea, when Deplo cannot add the webhook, the **Source** card shows
**Deplo could not add the push webhook**: the reason, the token access it needs, and the webhook
URL to add by hand.

## The deploy hook

<Image
  src={`${basePath}/screenshots/automatic-deployments/02-deploy-hook.png`}
  alt="The deploy hook URL with its rotate control"
  width={1728}
  height={1080}
  className="w-full rounded-lg"
/>

**Settings -> Advanced**, the **Build & triggers** card. On by default, for every app that does not
deploy from a GitHub App or a GitLab, Bitbucket or Gitea connection. **Copy deploy hook URL**, then:

```bash
curl -X POST \
  -H "Authorization: Bearer deplo_<token>" \
  https://deplo.example.com/api/apps/prj_3f9a1c2b7d4e8a06/deploy-hook/q9Vx2LkP0aZ7mT4wR8sYbN1cE6dH3fJu
```

Two secrets: the URL says *which app*, the bearer token says *who*. The token is an
[API token](/advanced/api-tokens-and-oauth) with `deploy_apps` (the **Deploy hook & CI** template).
A leaked URL alone deploys nothing.

**Rotate deploy hook URL** kills the old URL at once. The switch turns the hook off.

## Good to know

- **Watch paths fail open:** a push with no file list, like some tag pushes, deploys anyway.
- **A manual redeploy ignores every filter.**
- **Two apps can watch one repository** on different branches or paths: a normal staging setup.
- **`skipUnchangedDeployments`** skips pushes outside the root directory. It is in the
  [API](/api-reference/app-settings), with no switch in the panel.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Pushes do nothing | Look for **Deplo could not add the push webhook** on the **Source** card. `Set DEPLO_PUBLIC_URL to a public address` means the provider has no address to call. |
| The wrong branch deploys | The branch on the **Source** card, and the **Deploy trigger**. |
| The deploy hook returns `401` | The bearer token is missing, wrong, expired or revoked. |
| `403` | The hook is off, or the token lacks `deploy_apps`. |
| `404` | The URL was rotated, or the token is from another team. |
| `405` | Opened in a browser. `POST` only; the response shows a `curl` example. |

More in [Deploys and builds](/troubleshooting/deploys-and-builds).
