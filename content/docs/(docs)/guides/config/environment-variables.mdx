API keys, database URLs, feature flags, `NODE_ENV`. Deplo stores them encrypted and injects them
at build time and at run time.

## The four layers

When a name is set in more than one layer, the highest one wins:

1. **A shared variable added automatically**: one shared with two or more teams, or an
   instance-wide one. It shows on the app, read-only.
2. **The app's own variables.**
3. **A [shared variable](/guides/config/shared-variables)** the app has linked.
4. **A preview override**, on previews only.

## Plain and secret

| | Plain | Secret |
| --- | --- | --- |
| Shown again | Yes | Never, in the panel or the API |
| Copy | Yes: the button at the end of the value, no reveal needed | No |
| Edit or rename | Yes | No: delete it and add it again |
| [Note](#add-a-note) | Yes | Yes, the note is the one thing you can edit |
| Change the type | To secret: **Edit**, or **Make Secret** on selected rows | Never back to plain |

**A plain name that looks like a credential gets a warning icon**: `DB_PASSWORD`, `API_TOKEN`,
`S3_ACCESS_KEY_ID`. A name holding `PUBLIC`, `FILE` or `VERSION` is not flagged.

## Add a note

A note says what a variable is for, like `Public URL of the API` or `Issued by the payment
provider, rotated every 90 days`.

- **On the app's Environment page:** a variable with a note shows a note icon. The arrow at the
  start of the row opens it, with every line of the note.
- **When you add variables:** **Add note** under a row.
- **On an existing one:** **Edit note** in the open row, or the pencil. On a secret the pencil
  opens **Edit note**: the value still can't change.
- **Up to 1000 characters**, on as many lines as you like.
- **A note is never deployed.** Changing it needs no redeploy and leaves **Modified by** as it is.
  It still shows in **Activity**.
- **Anyone who can see the variable can read its note.** Never put a secret in one.

### Notes from a pasted .env

A comment becomes the note of the line it belongs to:

```bash
# --- Database ---
# Pool size for the API.
# Keep it under the database's connection limit.
DB_POOL=10
API_URL=https://api.acme.com  # Public base URL
COLOR=#fff
```

| Line | Note |
| --- | --- |
| `DB_POOL` | Pool size for the API.<br />Keep it under the database's connection limit. |
| `API_URL` | Public base URL |
| `COLOR` | None: with no space before it, `#fff` is the value |

- **The comment lines right above a line count**, each kept on its own line. One after the value
  wins over them.
- **A section title is never a note**: a comment that starts or ends with `---`, `===` or `***`.
- **A comment behind a blank line is kept, with a warning** under it: check it belongs to that
  variable, or **Remove** it.
- **A comment over 1000 characters is shortened**, and the dialog says so.
- **A line without a comment keeps the note** the variable already has.
- **Copy Plain** on selected rows writes the notes back as comments, so the copy pastes back the
  same.

## Variables from .env.example

When the app's repository has a `.env.example` in its root directory (or a `.env.sample`, or a
`.env.template`), Deplo reads it when the app is created and on every deploy from git:

```bash
# Postgres connection string.
# Use the pooled URL in production.
DATABASE_URL=
SMTP_PORT=587
```

- **Each name with no variable yet waits at the top of the list**, with a warning icon and `-` as
  its value. Nothing reaches the app until it has one.
- **Open the row to fill it in.** The comment above the name is its note, and a value the file
  gives, like `587`, waits in the field: **Save** makes it a variable. Turn on **Secret** first for
  a credential.
- **The bin removes a name you don't need.** It comes back only if the file drops it and lists it
  again.
- **A deploy never waits for them.** The app's **Deployments** page says how many still need a
  value.
- **A name added to the file later** shows up on the next deploy, and **Activity** says how many
  were found.

## Build time

A Railpack build gets every variable, so `NEXT_PUBLIC_*` and `VITE_*` work as they are. Two limits:

- **A Dockerfile build sees only the names it declares**, like `ARG NEXT_PUBLIC_API_URL`. Docker
  keeps build arguments in the image history, readable with Docker access to the build server.
- **Names that configure the build host never reach it:** `PATH`, `HOME`, and `DOCKER_*`,
  `BUILDKIT_*`, `BUILDX_*`, `COMPOSE_*`, `LD_*`, `XDG_*`, among others.

## Preview overrides

With [pull request previews](/guides/networking/pull-request-previews) (beta) on, the app's
**Environment** page gets a collapsed **Preview overrides** section: values used by previews only,
above every other layer. Typical use: point previews at a test database.

<Callout type="warn" title="A preview built from a fork inherits nothing">
For security reasons it gets only the plain preview overrides. If your app needs `DATABASE_URL` to
start, set it there as plain.
</Callout>

## Good to know

- **No secret variable can be revealed**, not even with `reveal_secrets`. That capability covers
  database connection strings, backup recovery keys and app backup downloads.
- **Deplo does not know which names your app reads.** A typo is a missing variable at run time.
- **Compose apps get the variables in every service.** A key the compose file sets itself keeps
  the compose value.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The app cannot see a variable | It was added after the last deploy. Redeploy. |
| The value is right in Deplo and wrong in the app | A higher layer sets the same name: a linked shared variable, a preview override, or the compose file. |
| A build-time variable is empty in the browser bundle | The framework only inlines prefixed names (`NEXT_PUBLIC_`, `VITE_`). With a Dockerfile, declare it with `ARG`. |

More in [Deploys and builds](/troubleshooting/deploys-and-builds).
