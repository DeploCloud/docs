The source most apps use. The agent clones the repository on the server that builds it.

| | GitHub App | GitLab, Bitbucket, Gitea (beta) | Repository URL |
| --- | --- | --- | --- |
| Repository picker and branch list | yes | yes | no, you paste the URL and type the branch |
| Deploy on push | yes | yes, a webhook per repository | no, use the [deploy hook](/guides/releases/automatic-deployments#the-deploy-hook) |
| Pull request previews | yes | no | no |
| Commands read before the first build | yes | no | only for a public `github.com` URL |

Pick the repository and the branch. Nothing connected yet? **Connect GitHub**, then **Personal
account** or **Organization**: Deplo creates the GitHub App, with nothing to copy, and
you choose which repositories it sees. **Use a repository URL** switches to the Git tile.

</Tab>
<Tab value="Git">

Pick the **Provider**:

- **Repository URL**: a public repository. Paste the clone URL, like
  `https://git.example.com/acme/site.git`, and the **Production branch**.
- **A connected provider**: pick the repository from its list.
- **Connect a git provider**: add a GitLab, Bitbucket or Gitea token right here. See
  [Git connections](/guides/git-providers/git-connections).

</Tab>
</Tabs>

</Step>
<Step>

### Set up the app and deploy

The **Set up the app** card shows the **App name**, the framework, the **Build command** and the
**Deploy command**.

- **A GitHub repository is read ahead.** The build command comes from your `package.json`, the
  deploy command from the framework's convention, never your `start` script. **Reset** empties a
  command and lets the builder decide.
- **Any other repository** shows **Detected at build time**: detection runs on the first build.

**Advanced** holds the server, variables, **Root directory**, build server, deploy trigger,
submodules and watch paths. Leave **Automatic deployments** on unless you release by hand, then
click **Deploy**.

</Step>
</Steps>

## New repositories on the Overview

Push a first commit to a new repository on a connected host: a dashed **New repository
detected** card appears on the Overview, before your apps. **Import** lists them, and **Import**
on one opens the wizard with that repository picked.

- **What:** up to 3 repositories created in the last 7 days, with at least one commit, that no
  app of the team deploys yet.
- **When:** Deplo checks each host at most every 5 minutes.
- **Where and who:** the top level of the Overview only, for members who can both create and
  deploy apps for the whole team.
- **X**, then **Hide this repository**: gone, in this browser only. **Stop suggesting
  repositories**: no more cards for you in this team. Turn them back on in **Settings -> Git**,
  **Suggest new repositories**.

<Callout type="info">
  A GitHub App installed on **Only select repositories** cannot see a new repository until you add
  it to the App's selection on GitHub.
</Callout>

**Settings -> Deployments**, the **Source** card. Change the repository, the branch, the **Root
directory**, or the source type itself. The app keeps its domains, variables and volumes.

**Save source** does not deploy. Click **Redeploy** when you are ready.

The rest lives nearby:

| Setting | Where |
| --- | --- |
| Build method | The **Build** card, below. See [Build settings](/guides/releases/build-settings#build-methods) |
| Deploy trigger, Include submodules, Watch paths | The **Releases** card, **Trigger** drawer. See [Automatic deployments](/guides/releases/automatic-deployments) |
| Server | **Settings -> General**, **Move**. Shown only when you have more than one server |

## Good to know

- **A `Dockerfile` or a Compose file in the repository is used.** That is what **Automatic**,
  the default build method, does. See [Build methods](/guides/releases/build-settings#build-methods).
- **A private repository needs a connection.** Its credentials are reused by every app on that
  host. See [Git providers](/guides/git-providers).
- **Two apps can track two branches of the same repository.** A normal way to run staging.
- **With a [build server](/advanced/build-servers) set, the clone happens there.**

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The picker says **No repositories accessible to this App.** | Click **Configure repository access on GitHub** and add the repository. |
| `Authentication failed` in the clone step | The stored token expired or was revoked. **Settings -> Git**, then **Test connection**. |
| Pushes do not deploy | On the **Source** card, look for **Deplo could not add the push webhook**: it lists what the token is missing and the webhook address to add by hand. |
| The build and deploy commands are empty in the wizard | The repository is not on GitHub. Detection runs on the first build. |

More in [Deploys and builds](/troubleshooting/deploys-and-builds).
