A role is a named set of [capabilities](/reference/capabilities), owned by the team, that any number of members hold. Membership mutations take a `roleId`. The older `role` + `capabilities` pair still works and lands on the matching role when there is one.

<Callout type="info" title="Inviting somebody new is not a mutation">
  Registering an account that does not exist yet goes through a registration link, see [Users](/api-reference/users). These mutations put an account that already exists onto the team.
</Callout>

## Members

### `members`

Any signed-in principal. Returns [`[Member!]`](/api-reference/types/objects#member).

Members of the active team, oldest first.

```graphql
query {
  members {
    userId
    username
    roleName
  }
}
```

## Roles

On `updateRole`, every omitted optional field means leave it as it is: omit `capabilities`, `requireTwoFactor` or `scope` and they are untouched. Send `clearScope: true` to make a role reach the whole team again.

### `teamRoles`

Any signed-in principal. Returns [`[TeamRole!]`](/api-reference/types/objects#teamrole).

Every role of the active team - defaults first, then the team's own.

```graphql
query {
  teamRoles {
    id
    name
    capabilities
    memberCount
  }
}
```
