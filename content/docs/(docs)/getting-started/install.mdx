## Install it yourself

One shell script, run as root on a fresh Linux server.

<Tabs items={['Quick install', 'With your own domain']}>
<Tab value="Quick install">

```bash
curl -fsSL https://deplo.build/install.sh | bash
```

The dashboard comes up on a generated HTTPS address such as `https://deplo-cb00710a.deplo.site`
(for IP `203.0.113.10`). The installer prints the real one.

An IPv6-only server needs nothing extra. On a server with both, IPv4 is the default and
`bash -s -- --ipv6` picks IPv6. See [IPv6](/reference/installers/install#ipv6).

</Tab>
<Tab value="With your own domain">

Point an A record at the server first, then run:

```bash
curl -fsSL https://deplo.build/install.sh | \
  DEPLO_DOMAIN=deplo.example.com ACME_EMAIL=you@example.com bash
```

The generated `deplo.site` address stays as a **Backup address**. Turn it off in **Settings ->
Deplo -> Advanced**.

`localhost`, `*.local`, `*.localdomain`, a bare IP or a name without a dot is not a domain: the
installer warns and keeps the generated address.

</Tab>
</Tabs>

<Callout type="info" title="Already have Deplo running?">
  Don't run this script on a second machine. To add a server for your apps, a
  [build server](/advanced/build-servers) or a backup host, paste the command from
  **Settings -> Servers** on it instead. See [Add a server](/operations/servers/add-a-server)
  and [Server roles](/advanced/server-roles).
</Callout>

## What you need

| What | Requirement |
| --- | --- |
| A clean server | <Os name="ubuntu">Ubuntu 24.04 LTS or newer</Os>, <Os name="debian">Debian 12 or 13</Os>, or one of the other <Os name="linux">[supported distributions](/reference/supported-operating-systems)</Os>, `x86-64` or `arm64`, with `systemd` for the [agent](/concepts/servers-and-the-agent). |
| Size | **2 cores, 4 GB of RAM, 30 GB of disk** minimum, **4 cores and 8 GB** comfortable. Deplo itself fits in about 1 GB; the rest is for your apps. The installer warns below the minimum and **refuses below 8 GB free on `/`**. |
| Ports | `80` and `443` reachable from the internet, nothing else. Behind a home or office router, serve the panel through a [Cloudflare Tunnel](/operations/cloudflare-tunnel). |
| Outbound HTTPS | `ghcr.io` (the image), `github.com` (the server agent), `get.docker.com` (when Docker is missing) and Let's Encrypt. The preflight checks all but GitHub. |
| A domain | Optional: the generated `deplo.site` address works from the first deploy. |

To check a machine without changing anything, run only the preflight:

```bash
curl -fsSL https://deplo.build/install.sh | bash -s -- --check
```

## What the installer does

| Change on the host | Why |
| --- | --- |
| Installs Docker if absent | From `get.docker.com`, then enables the service |
| Sets `default-address-pools` in `/etc/docker/daemon.json` | Docker's defaults allow about 31 networks and Deplo uses one per Environment. An existing pool config is left alone; the old file is kept as `daemon.json.deplo-bak` and the new one checked with `dockerd --validate` first |
| Creates the `deplo` Docker network | For Traefik and the control plane only. Apps get their own [Environment network](/advanced/network-isolation) |
| Enrolls this machine as a server | Waits for `/api/health`, then runs the agent installer against the panel on `127.0.0.1` |

Then four containers come up:

| Image | Purpose | Exposed ports |
| --- | --- | --- |
| `postgres:16-alpine` | The control plane's database | None |
| `ghcr.io/deplocloud/deplo:latest` | The control plane | `3000` and `3101`, on `127.0.0.1` only |
| `traefik:v3.7.17` | Routes your apps' domains | `80`, `443` |
| `tecnativa/docker-socket-proxy:v0.5.0` | Lets Traefik read container labels, read-only | None |

Neither Traefik nor the control plane gets the Docker socket: see
[How Deplo works](/concepts/how-deplo-works).

## How to update

**Settings -> Deplo -> Updates** installs a new version with one button, and the panel tells you
when one is out. Running the install script again also updates in place. See
[Update](/operations/update) for the server agents and version pinning.

## Run it with Compose instead

`docker-compose.yml` in the repository runs the control plane and its Postgres, routed by labels
through a Traefik you already run on the external `deplo` network.

```bash
docker network create deplo
export DEPLO_DOMAIN=deplo.example.com   # required: the only address it serves
export DEPLO_SECRET=$(openssl rand -base64 48)
export DEPLO_DB_PASSWORD=$(openssl rand -base64 24)
export DEPLO_SETUP_KEY=$(openssl rand -hex 16)   # then open /setup?key=<key>
docker compose up -d
```

Then enroll the host yourself from **Settings -> Servers**, like any other machine. Good to know:

- **One port is published, `3101` on `127.0.0.1`**, for this machine's own server agent.
  `DEPLO_LINK_PORT` changes it.
- **`DEPLO_SETUP_KEY` is optional.** Unset, Deplo derives one from `DEPLO_SECRET` and prints the
  link at boot: `docker compose logs deplo | grep setup`.
- **`DEPLO_SECRET` cannot be rotated.** It derives every encryption key, session signature and
  agent certificate: change it and stored secrets become unreadable. Back it up (the installer
  keeps it in `/opt/deplo/.env`).
- **The domain must resolve first.** Let's Encrypt validates over HTTP on port 80.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `docker compose` not found | Compose v2 is required. Install Docker's own packages, not a distribution's `docker.io`. |
| The dashboard does not answer | On the server, `curl http://127.0.0.1:3000/api/health`. If it answers, look at the proxy: `docker logs deplo-traefik`. If not, `docker logs deplo-deplo-1`; a failure to reach Postgres is the usual cause. |
| The domain shows a certificate warning | The A record does not point at this server yet, or port 80 is closed. |
| Agent enrollment failed | Not fatal: the dashboard still comes up and says so. Run the installer again to retry. |

More in [Servers and agents](/troubleshooting/servers-and-agents) and
[Domains and TLS](/troubleshooting/domains-and-tls).
